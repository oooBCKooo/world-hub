# 独立软界面模块

这里有两个可以分别导入通信管理界面的模块：`desktop` 是原生窗口宿主，`counter` 是使用它的独立计数程序。计数、视图状态和窗口管理属于这些程序；Hub 只传递消息。

模块采用稳定 ID 和确切版本，`example.soft-ui-desktop@0.3.0` 与 `example.soft-ui-counter@0.3.1`。计数器新增默认连接，因此使用新版本，已交付的 `0.3.0` ZIP 保留原有内容。桌面宿主当前正式部署平台为 Windows x64，使用固定 Electron 44.7.1。源 ZIP 不携带依赖缓存、平台二进制、私有凭据或运行状态；在通信管理界面审阅所需环境并完成支持的依赖准备。

先在通信管理界面导入桌面宿主 ZIP，再导入计数器 ZIP。计数器的 `deployment.json` 已指定默认宿主身份、确切版本、能力绑定和主题映射；本机唯一匹配时自动填好导入审阅，多个匹配实例则选择一个，缺少宿主会提示需要下载并导入哪个模块。完成导入后，先启动宿主，再启动计数器。也可以发布预接线的模块组，把完整配置放在组配方中，用户一次审阅导入。新计数程序加入已运行宿主后，需要重新审阅并重启宿主，让其读取新的允许主体；程序不会凭名称信任未绑定的发送者。

`deployment.json` 是可选作者部署层：它提供中英文标题、公开设置、默认通道、桥槽权限、默认连接和固定环境方案。程序从私有 Runtime 配置读取实际通道、通信身份和能力绑定；主体 ID 由本机管理器生成。默认通道可以在部署时修改，它们属于应用契约，不是 Hub 的内建消息种类。

应用协议 `soft-ui/1`：业务程序向绑定的提供者注入 `view.open` / `view.update` / `view.close`，内容含 `viewId`、递增 `revision`、标题和受验证的组件树；提供者将 `ui.event` 注入回该视图所属主体，内容含唯一 `eventId`、视图修订、控件 ID 和操作。业务程序先持久化状态和待发描述，再完成传输；窗口宿主先持久化视图，再确认消息。SDK 消息游标与程序快照分开保存。界面动作被 Hub 接收不等于业务计算已完成，显示更新才体现计数程序的新状态。

允许子进程的部署使用 `owned-children` 声明及专用 Runtime 生命周期适配器。Windows 用先暂停、后加入 Job 的方式创建程序，并确认整个所属 Job 退出；Linux 使用持续存活的所属进程组监督者。它是进程生命周期管理，不是沙箱。Linux 主动调用 `setsid` 逃离组的程序不受此组管理，未支持的平台拒绝这种部署。

作者构建命令：`node scripts/release/build-soft-ui-modules.mjs --output <新的输出目录>`。两个 ZIP 附带 SHA-256 文件，均可单独导入。修改模块源码后须发行新版本；不要覆盖已登记版本的内容。
