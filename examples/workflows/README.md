# 外部多轮工作流示例

工作流程序通过自己的 mod 选择每轮参与程序、发起请求、汇总分支并返回成果。每个步骤都由独立外部进程处理，跨程序通讯经过真实 Hub 和 mod；同一个程序可以有多个 mod。

Hub 不解释工作流计划，不替应用选择下一步，也不判断业务完成。应用自身保存检查点、处理失败和不确定结果。示例与测试只证明已执行的本地路径，不能推导任意工作流的执行保证。

```powershell
npm run demo:workflow
node examples/workflows/run-flows.mjs
```

演示运行一个三轮、多程序工作流并保存经过调用方核对的成果。完整 runner 执行十个测试场景，包含逐跳转交、嵌套调用、回访、并行分支、离线重启、附件和应用检查点。默认 `npm test` 也运行这个完整 runner，不要求 DSH、Python 或 PowerShell。

每次执行将报告和成果写入 `.artifacts/evidence/workflows*/` 下新建的目录；可以通过 `--evidence <目录>` 指定输出。输出不进入源代码仓库。测试结束后收起自身拥有的 Hub 和程序。

提供者自己决定信息的释放，转交、抽取、ACK 和业务结束不代表 Hub 可以清理。检查点恢复经过测试的范围是已完成检查点，不能据此承诺崩溃窗口中的业务 exactly-once。
