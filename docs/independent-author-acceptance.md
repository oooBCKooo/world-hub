# 独立作者与新用户验收

这份验收验证独立接入与可理解的使用流程。自动测试、AI 作者 fixture、作者样板和项目维护者演示各有用途，均不能作为真人第三方独立验收的替代证据。

## 作者资料包

维护者运行 `node scripts/release/build-independent-author-kit.mjs --output <新的目录>`，将产生只含公开能力契约、JavaScript/Python SDK 与文档、许可证和记录模板的资料包。资料包不含 Hub、目录、组装器、已有提供者、作者样板或测试答案。

维护者另外提供临时测试部署的通信地址、身份／凭据、模块 ID、目录主题、业务主题和授权调用方。它们是部署信息，不是业务实现。不得将真实生产凭据写入资料包、公开记录或共享制品。

参加者应未参与本项目开发；记录其先前了解程度和允许阅读的材料。按相同 `text.statistics@1.0.0` 契约，从头实现一个能力提供者，再以配置替换原提供者。作者可以选择 JavaScript 或 Python；若两位作者参加，分别实现并分别验收，不能把复制同一作者代码算作独立实现。

## 验收步骤

| 编号 | 操作 | 需要保存的事实 |
| --- | --- | --- |
| A1 | 只阅读资料包与部署说明，编写提供者 | 材料清单、语言／版本、独立来源声明、开始时间 |
| A2 | 登记能力并响应实际调用 | 真实主体、会话、请求与响应序号、契约、业务结果 |
| A3 | 测试空文本、Unicode、换行、超限与错误版本 | 精确结果或契约错误；不得把 ACK 作为业务成功 |
| A4 | 只改配置，替换已有提供者 | Core、来源和消费者源码摘要保持相同 |
| A5 | 停止并重新启动提供者，更新登记会话 | 新会话实际调用；旧租约与迟到响应不冒充当前结果 |
| A6 | 发布、发现、获取和生成独立实例 | 制品摘要、公开许可、来源观察、运行时审阅、完整调用结果 |
| A7 | 未熟悉项目的用户操作安装、诊断、审阅、启停、日志、备份与恢复 | 每步完成／求助／失败，耗时、截图、恢复后的成果和新身份 |

维护者执行隐藏的互操作检查，保留失败和求助记录。参加者不应在实现之前看到参考提供者或隐藏测试源码。测试部署应为专用环境，结束后关闭其所属进程，撤销临时凭据；不使用或删除其他人的实例。

## 接受结果

“真人独立接入通过”要求 A1–A6 有参加者来源声明和实际通信证据；A7 单独决定新用户使用验收是否通过。只提交源码、截图、单元测试或维护者代操作不满足全部条件。

报告不需要真实姓名；可以使用参加者自选代号。公开报告应排除凭据、私有路径、个人对话和业务数据，保留必要版本、源码／制品摘要、错误类型及修复事实。

当前尚无真人参加者；按用户决定，此项保留待验收。后续实际记录前不得将其改为通过。
