# 通信管理：一个本机 Hub 与模块组

[English](launcher.en.md) · [模块接入与工作台](launcher-deployment.md)

本机 Hub 的 `/manage` 通信界面管理模块、实例、分组、接线和管理器拥有的进程。所有本机实例共用这一个 Hub。模块管理属于管理层；Hub 通信内核不读取分组、不解释应用业务，不把模块加载为内核插件。独立 Launcher 已退出当前产品。

## 启动

```powershell
world-hub --open
# 源码：node bin/world-hub.mjs --open
# 明确指定数据目录：world-hub --data-dir ./my-hub --port 0 --open
```

未指定配置时，CLI 在当前目录的 `world-hub-data` 中保存配置与数据；`--data-dir <可写目录>` 可明确选择数据根，`--config <文件>` 选择自己的 Hub 配置。`--port 0` 让系统分配 Hub 监听端口，按终端输出打开 `/manage`。已有配置不会被参考配置覆盖。完整选项见 [npm 使用](../npm.md)。

保留终端运行，Ctrl+C 等待正常停止。管理器清理自己拥有的模块进程，外部程序由自己的宿主管理。不要对同一个配置、数据目录或监听端口重复启动 Hub。旧 `ui` 子命令与 `--root` 不是当前 CLI 选项。

## 导航与对象

| 界面功能 | 用途 |
| --- | --- |
| 拓扑画布与信息流 | 查看 Hub、程序、模块桥和实际通信 |
| 本地导入与在线工坊 | 获取模块／模块组制品，选择需要的发行版本并审阅导入 |
| 模块抽屉 | 查看实例参数、接线、进程、日志和真实桥会话 |
| 模块组与范围选择 | 引用已有实例，组织管理范围和组启动计划 |
| 接线与启动计划 | 直接调整实例配置、能力绑定、成员选择和执行顺序 |
| 版本、恢复与卸载 | 审阅升级、降级、历史回退、默认接线恢复及单个／整组卸载 |
| 用户通信工作台 | 使用页面自己的模块桥发布、抽取、调用、注入与传输附件 |
| 环境与目录选择 | 查看本机解释器，选择或浏览本地路径 |

模块版本描述制品；实例的 `programId` 描述一次独立登记；本地配置修订描述公开设置和接线的变更。它们都不是 Hub 发行版本。更新模块源码需重新审阅，不通过修改 Hub 版本来表达。

## 模块组与共享成员

组只保存实例引用和管理信息，不拥有 Hub、凭据、数据或进程。一个实例可加入多个组；启动已经运行的共享实例不会再执行一份。加入组不授予通信权限，也不证明该实例业务就绪。

停止组、移除成员或修改共享配置时，审阅中列出其他受影响的组和消费者。组删除不等于卸载模块或清理业务数据。需要不同参数、数据或身份时，在模块库登记另一个实例。

启动计划区分成员、精确执行顺序和前置关系。编排只启动被选择且采用常驻策略的成员，其他成员可稍后手动启动。按需模块的调用唤醒须使用生命周期客户端并由本机用户授权；普通业务消息不会自动启动程序。作者可提供运行默认值，用户可覆盖，见[常驻与按需运行](modules.md#常驻与按需运行)。计划失败与业务失败分别观察，Hub 不替模块决定业务重试。

## 审阅、权限与真实状态

导入和下载只获取源码。登记、配置保存与启动各自按当前内容审阅。摘要或配置改变后重新检查；不能把旧审阅自动转给另一个版本。

公开参数不得携带凭据，秘密留在本机私有运行配置。页面中的权限声明不是 OS 沙箱。程序是否启动、是否自报就绪以及是否真正建立模块桥会话是不同事实；接纳、ACK 和探针成功也不等于业务成果。

管理界面区分受管实例与自行接入的程序，可观察真实连接并配置精确通道授权。撤销通信授权不等于终止外部程序进程。手动发布、调用、注入与附件操作属于管理页面自己的模块桥。

## 路径、选择与退出

目录／文件字段支持选择窗口、浏览、最近使用和有界候选发现，不全盘扫描。服务器返回的路径仍需当前内容检查，来源摘要不能由浏览器伪造。

多版本卡片保留仍然可用的当前选项。失效时优先选择同一实例、目录或来源制品，其次选择组内其他可用项，并显示提示；自动选择不下载、不升级、不启动，也不继承旧执行授权。

停止前保存尚未提交的界面修改。管理器的私有数据目录可能包含身份、凭据、游标与业务数据，不能作为公开模块直接分享。异常退出时先核对终端报错、数据目录及真实进程归属，不根据历史 PID 终止未知进程；当前 CLI 不提供旧 Launcher 的锁检查和清理子命令。数据保留与升级步骤见[部署](../deployment.md)和[分发](../releases.md)。

## 当前边界

整合包、每包独立 Hub、模板生成和整包 Runtime 不再是当前产品入口。不转换旧整合包或模板为新的模块组，也不自动删除它们的源码或私人数据。需要旧组合中的程序时，分别取得作者提供的当前模块版本再登记。

普通外部程序无需采用管理器的模块声明即可通过模块桥接入。见[独立程序接入](external-programs.md)、[模块声明](modules.md)与[通信规格](../specs/index.md)。
