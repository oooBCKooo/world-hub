# 通讯可靠性、权限与运维边界

本规范只约束通讯，不定义外部程序业务成功、执行策略或恢复模型。

## 有界投递

默认delivery为 `bounded_ack`：按主题匹配、顺序投递、确认窗口有限、保留历史内可按游标恢复。旧名称 `at_least_once` 作为相同模式的兼容别名接受，不能据此宣称无条件至少一次。`at_most_once`不补课、不保留确认窗口。

窗口满时，实时信息可能不投递，明确overflow给出dropped区间和原因，通常追加通讯gap记录。gap记录受同一存储容量与写盘边界限制；追加失败记录运维trace，不能把已经成功接受的主消息反报为发布拒绝。这是当次投递缺口，不是删除已接受消息的许可。客户端可记录缺口或重新订阅/重连补课；未释放的消息仍受存储保护。提供者已释放并被历史轮转清理的消息可能形成留存缺口。不承诺自动补漏或端到端恰好一次；程序决定如何处理重复、过期和缺口。

订阅是独立的通讯资源。两个订阅重叠时，同一 seq 可分别投递，各自维护 ACK 窗口和游标；一个订阅内的多个过滤器不会为同一记录重复投递。实时订阅与历史补读并行、重连以及 SDK `call()` 临时回应订阅与普通订阅重叠，都可能让程序多次看到同一记录。桥不跨订阅决定业务已处理。程序若需要一次处理，应协调并发重复，成功后分别确认每份投递；跨进程或重启后的幂等凭据与副作用提交由程序自行持久化。进程内示例见[接入说明](../onboarding.md#重叠订阅与程序去重)，ACK 和去重都不授予 release 权。

`/status` 另返回 `counters.gapLogFailures` 和 `lastGapLogFailure`（最近失败缺口序号、区间、订阅、原因、错误码和时刻）。它们只观测本次进程，重启归零；trace 有界，不构成独立持久诊断日志。缺口来源包括实时窗口／补课队列溢出、通讯停滞和已获提供者许可的历史清理，不能笼统声称都来自提供者意图。

补课使用独立扫描位置，不凭已送出信息代替已确认信息。补课期间的新信息进入有界队列，历史扫完后按序冲洗；窗口满时保留排队项等确认，超出队列明确报缺口。扫描完成后caught_up不会自行推进确认游标。补课窗口持续无进展超过catchUpIdleMs（默认30秒）明确CATCHUP_STALLED并关闭，是通讯资源回收，不是业务时钟。

## 日志与原文

seq在本枢纽单调分配，发布追加和路由按序执行；分段写入、轮转和查询串行。写盘失败返回HUB_INTERNAL，未提交信息不可被历史查询读到；已分配序号可有空洞，不回退或复用。

发布可以没有消费者。成功接受的消息默认保留并受保护；之后按游标抽取是非破坏读取，可有多个独立读者。发送、读取、ACK、`caught_up`、`at_most_once` 的自动游标、桥断开和订阅清理都不解除保护。提供者通过 `release` 明确许可回收；释放授权和元数据写入也按通讯存储操作串行处理。

JSONL只保存通讯记录。bodyRaw作为可逆JSON字符串保留body原始JSON文本，body是兼容查看视图。补课以原文为权威，不用查看视图重新编码。原文可含换行/高精度数值，日志仍是一行一条JSON。旧日志没有bodyRaw时从原行提取body。bodyRaw不作为业务字段传给接收程序。

消息内部 `owner` 记录稳定提供者通讯身份；释放状态保存在日志元数据 sidecar。凭据模式以凭据标识归属，单身份模式以bridgeId归属；同一凭据的不同实例可以释放该凭据提供的消息。owner不进入投递body，也不是程序业务状态。旧记录缺少owner时回退from身份，不凭空恢复旧凭据关系。释放整批验证，无权或不存在的任意序号导致全批失败；元数据提交失败不把记录视为已释放。

启动扫描保留分段的顶层序号和内容，不相信载荷内部seq或旧manifest。半写的活动尾行先修复再追加。tail/历史查询涵盖保留段，轮转首条必须立即可见。range的truncated只表示保留缺失，hasMore只表示批次仍有更多记录，二者不可混同。

segmentMaxBytes是轮转目标，默认8MiB；segmentMaxCount默认8。一条超过目标的记录独占一段。段数上限不能用于覆盖未释放记录。只有最旧历史段中的消息都已获得提供者释放许可，才可在容量轮转时清理该段；若最旧段仍含受保护记录，则不跳过它删除后面的段来制造历史洞。需要新段而无法清理时，先以 `LOG_CAPACITY` 拒绝新publish，不提交新记录、不回published，既有记录继续保留。释放后容量是否立即可用，取决于阻挡轮转的整个最旧段是否已满足清理条件。

release不立即删除，仍保留的已释放记录可继续被读取；只有之后满足容量轮转条件才实际清理。删除旧段失败不反报已提交发布为失败；存储清理错误时拒绝依赖该清理的新追加，不通过丢弃受保护记录恢复容量。

当前容量属于单个枢纽的全局日志。最旧段受保护时，LOG_CAPACITY可能拒绝所有提供者的新发布；已保留信息的抽取、ACK、release和连接管理仍可进行。这是参考实现明确接受的容量隔离限制，并非只对阻挡者限流。提供者离线、崩溃、长期不释放或凭据被移除，都不会自动过期其记录。恢复方式是同一稳定身份重新接入并按自己的策略释放，或部署方扩大日志容量后重启；被移除身份需要恢复其通讯凭据才能释放。未实现每提供者独立容量、在线扩容或管理员强制删除；不擅自替提供者设forceReleaseAfter。

启动输出和 `/status.storage.log` 显示最旧段未释放主体及序号范围、未使用段位和活动段距轮转目标的字节。后者不是精确剩余容量；当前段仍可容纳多大的记录取决于实际编码字节数，超过目标的一条记录可独占段。管理页显示同一摘要。详见[部署与容量说明](../deployment.md)。

内存缓存整个保留窗口，解析对象和原文副本的内存开销高于磁盘字节数。默认 `log.enabled:true` 保存消息、归属和释放元数据，重启后恢复保护状态。`log.enabled:false` 采用同样的本次进程内存保护/释放/容量规则，但进程结束后数据不保留，不能宣称跨重启留存。

释放元数据和manifest采用临时文件、同步及原子替换；释放元数据缺失时默认保护，损坏时LOG_RELEASE_CORRUPT拒绝启动，不猜测释放许可。消息追加未提供fsync/断电耐久性承诺，未交付日志内容校验和、冷归档、高可用或跨枢纽复制。受保护留存不等于无限磁盘容量，也不构成程序业务状态库。历史抽取和重连可能重复投递，不能声称提供游标文件就不丢不重。敏感撤回、全副本删除和独占领取尚未实现；提供者的释放时机、业务去重和单消费者策略由程序决定。

## 授权与观测

默认拒绝未登记桥；token与主题规则由配置确定。订阅过滤器必须完全被授权上限覆盖，注册不能扩大权限。多实例共享凭据授权与配额，但连接身份唯一。role、displayName、body.kind不参与授权。

已登记而没有 token 的身份只允许回环接入，并标记 `authenticated:false`。这是受信本机模式，不能抵御本机程序自报允许的身份或同名接管；载荷来源与通讯来源的绑定也不能补出缺失的认证。配置 token 后才会校验对应凭据。消费程序是否认可某主体提供某种业务信息仍由该程序自行决定，Hub 不内置上下文来源、系统提示词或其他业务资格。

acl.bridges与acl.credentials不得使用同名键，配置歧义明确拒绝启动；两类键都须符合稳定桥标识语法，不能包含 Hub 使用的实例冒号。声明可从/status的bridges[].channels及本机调试页查看；它表达桥的通讯接口意图，不保证生产者持续在线或历史永久存在。

release只能操作当前通讯身份归属的保留消息。读取主题权限、消费确认、临时实例身份或载荷中自称provider均不能授予他人的释放权；无需把程序业务保留策略注册成Hub类别。

仅本机回环调试端点：`GET /`、`GET /status`、`GET /log?limit=N`。即使WebSocket监听0.0.0.0，非回环HTTP请求也返回403。它们面向可信本机运维，可查看全部通讯正文，**不提供同机不同应用间的主题隔离**；调试页不是业务程序接入通道，也不是外部业务界面。

需要更细隔离时，程序通过有主题权限的桥订阅；远程运维应独立设计认证与脱敏，不把只读等同有授权。当前只有静态token，TLS需部署方另加可信隧道/代理；不宣称可直接安全公开部署。

## 本机通讯管理

`GET /manage` 与 `/manage/api/state` 提供通讯管理界面与元数据；选择记录时通过 `/manage/api/message?seq=N` 按需查看保留中的原文。`POST /manage/api/bridge` 只接受暂停、恢复和精确连接断开；`POST /manage/api/annotation` 只保存桥名称与 N:M 程序关系注记。管理不执行程序、不修改 ACL、不代发 ACK 或 release。暂停凭据主体会断开其全部实例并拒绝新实例；恢复仍采用原 ACL，程序由自己的 mod 决定是否重连。

这些入口仅接受回环来源，校验本机 Host、同源 Origin 与跨站请求标记；变更必须携带当前管理操作令牌，JSON 请求体上限 16KiB。不返回 ACL token 或配置秘密。它面向可信本机运维，不提供同机不同账号或程序的权限隔离。畸形请求 URL 返回 400，不导致枢纽退出。

`management.json` 原子保存暂停集和视图注记，成功保存之后才应用暂停。默认跟随有效日志目录，包括 `--log-dir` 覆盖；配置 `management.stateFile` 可单独指定。缺失时采用空暂停与配置的初始注记，已有文件无效则拒绝启动，不猜测已暂停主体应恢复开放。消息日志关闭也不关闭管理设置持久化。视图关系不证明程序运行状态。详细范围与验证要求见[通讯管理](management.md)。

## 限额

| 配置 | 默认 | 边界 |
| --- | --- | --- |
| maxPayloadBytes | 1MiB | body原文UTF-8字节；示例配置256KiB |
| maxSubscriptionsPerBridge | 64 | 单连接订阅数 |
| maxFiltersPerSubscription | 16 | 每次订阅过滤器数 |
| maxPendingDeliveries | 512 | 连续确认前缀的投递窗口占用 |
| maxCatchUpMessages | 5000 | 单批补课条数上限；不是整次历史总量 |
| catchUpBatchSize | 256 | 调度批次上限，与上述上限及剩余窗口取最小值 |
| catchUpIdleMs | 30000 | 补课窗口无进展回收时间 |
| maxQueuedFrames / maxQueuedFrameBytes | 64 / 8MiB | 单连接等待处理的输入帧/字节上限，超限明确关闭 |
| maxConnections / maxBridges | 256 / 128 | 传输连接/接入身份总数 |

显式通道声明最多128项；release每批1–128个序号；关联标识最多512字符；WebSocket完整消息最多4MiB。分片按累计长度计限额，二进制帧明确拒绝。没有QPS限流、业务预算或按信息种类限流；后两者不属于枢纽业务。

配置及权限变更需重启；本机管理接入暂停与视图注记可即时更新。程序退出/崩溃由自身负责；断开的通讯声明、订阅和计时器由枢纽清理，不清理该程序提供的受保护消息。程序不能依赖退出钩子才保存已处理游标。

## 定向与大对象通讯

请求与注入同时受到目标身份和主题 ACL 约束，实时、补课及附件读取采用相同地址检查。回应以保留中的请求序号验证提供者身份并推导返回地址，载荷中自报的身份和关联字符串不能赋权。精确 session 不跨重连；稳定 principal 目标允许后来抽取。请求超时、回复或 ACK 都不解除提供者保护。

回应沿用原请求主题，也必须匹配调用方的订阅才能投递；`requestSeq` 只建立可信关联，不绕过主题 ACL、不自动推送或另开回程主题。双方均需该主题的发布与订阅权限。授予订阅权限不授予读取第三方定向正文的权力，target principal/session 在实时和历史路径继续核验；同主题广播则按主题权限可见。现有 ACL 未提供 `fromPrincipal → toPrincipal` 允许关系，需要此类进一步限制的部署应另行提出通讯权限需求，不能将现有主题权限误写为可旁观全部定向流量。

大对象强制独立磁盘保存，消息日志只缓存附件描述符；普通消息正文的现有内存限制仍存在。blobs 默认单对象 1 GiB、总预约 2 GiB、128 个对象、块 256 KiB（可配到 512 KiB），预约包括 partial。对象释放与消息释放独立，新消息不能引用已释放对象；发布提交期间使用短期通讯 pin 防止并发容量回收，提交结束后继续尊重提供者的明确释放决定。

`blob_release` 不立即删除：已有保留消息授权的读者在实际回收前仍可读取，对象回收后原消息可能仍在而读取返回 `BLOB_NOT_FOUND`。读者以 `blob_read(messageSeq,id)` 的实际结果为准，不能使用只允许提供者调用的 `blob_status`。附件池满时提供者释放、后续 `blob_begin` 可按需回收，调高配置上限才需重启。启动输出、`/status.storage.blobs` 与 `/manage` 显示预约、空闲对象位／字节、已释放及无 pin 的可回收预约量；这些不授予释放权。

WebSocket 出站缓冲默认限 8 MiB，超过上限立即断连；对象读取逐块响应而不是排队整个文件。大对象读/写/校验在独立对象存储队列中串行，普通消息发布不依赖该队列；附件发布和其他对象操作可能等待已有对象操作完成，不承诺公平调度或高并发吞吐。详见[请求／大体积协议](directed-and-bulk.md)，验证范围见[验证说明](../verification.md)。
