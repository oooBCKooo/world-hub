# 模块本体、配置与数据

这些是本机管理层和社区的分发资源，Hub Core 不读取这些文档，也不解释模块业务、业务数据或业务工作流。程序通过枢纽桥通信的契约保持独立。

## 三类资源

| 类别 | 内容 | 范围与版本 | 导入后的行为 |
| --- | --- | --- | --- |
| 模块本体 | `module.json`、程序和枢纽桥文件 | 本体 ID、精确版本、源码摘要 | 缓存到统一本体库，不注册或启动实例 |
| 模块配置 | 单个 `configuration.json` | 配置 ID、独立版本、global/local | 保存；另行映射、预览、应用 |
| 模块数据 | `data.json` 与 `data/<逻辑实例>/` | 数据 ID、独立版本、global/local | 保存；另行核对兼容性、预览、恢复 |

全局表示当前全部本机实例，局部表示明确选择的实例；两者共用一个 Hub 与本体库。相同本体 ID、版本与摘要只缓存一次，可以被多个配置引用。实例仍有各自的身份、状态目录、设置和运行状态。配置不嵌入源码，不打包管理凭据。公开社区仅接收 module/configuration/data；私人 backup 只用于本机导入导出。

本体锁的 `digest` 是 `SHA256(JSON.stringify(await collectSourceFiles(moduleDirectory)))`，不是制品 JSON 的 SHA-256，也不是包含解释器和部署检查的本机接入审阅摘要。同一 ID 与版本的不同内容会被拒绝，需要新版本。数据版本的身份包含实际文件内容。

配置结构见 [configuration.schema.json](../ecosystem/configuration.schema.json)，数据结构见 [data.schema.json](../ecosystem/data.schema.json)。可调整启动计划、常驻/按需默认值、参数和接线。应用配置不会授予执行权限、安装依赖或启动程序；这些操作仍须使用本机的相应管理入口。执行默认值只在新建实例时初始化，不覆盖既有实例的用户运行策略。

## 切换与叠加

1. 导入或捕获配置，保存所需版本。
2. 配置中的逻辑实例映射到现有实例，或指定新的实例 ID。多个匹配候选必须明确选择；同一配置不能把两个逻辑实例映射到同一本机实例。
3. 独立导入所需本体，或从已配置并启用的软件源补齐精确版本和摘要。下载不执行代码。
4. 选择本次替换的生效配置。未选择替换的配置仍生效；修改它们共享的实例会形成冲突。
5. 预览差异、缺失本体、冲突、创建实例和停止范围，确认后应用。实际源码和本机配置发生变化会使旧预览失效。

未改变的运行实例保留原进程、凭据及桥连接。需要修改的运行实例，以及被替换配置独占的运行实例，必须先确认停止；无法确认所有权或退出时不继续。切换默认保留业务数据，不自动恢复配置可声明的数据引用。声明的数据引用是供选择的制品指针，恢复始终是独立操作。

全局配置更新本机全局启动计划；局部配置保存为本机配置范围的启动计划。当前已有但未纳入全局配置的实例仍保留，默认不参加新的编排。取消生效只移除配置的活动引用，不改当前进程、接线或数据。配置历史与保留选择仍在。

## 保留与清理

“已保存”“已保留”“当前生效”分别记录。保存许多配置不代表同时运行。当前生效配置、用户选择保留的配置、额外保留实例及运行/所有权不明的实例构成保留根；继续沿能力绑定保留传递依赖，支持共享依赖和循环引用。

例如 A 引用甲乙，B 引用乙丙：同时保留 A、B 时三者都保留；只保留 A 时丙才可能清理。清理不是卸载某一配置名下的全部模块。

清理先预览，再提交注销登记和可选的无引用本体缓存移除。保存的配置文档不会被改写，未保留配置可显示缺失本体。运行实例不在清理候选中。私有实例目录、业务数据、身份文件、历史版本和恢复快照不会随清理删除。直接卸载入口也必须尊重生效或保留配置的引用。

注销前在实例私有目录记录已停止的登记元数据与身份文件摘要。再次应用配置时，明确列出可重新登记的实例；仅在记录、实际源码、精确本体锁与身份文件一致时复用原身份和数据。普通残留目录或被改过的记录形成阻止项，不覆盖、不自动接管进程。用户可改选新的实例 ID，再单独选择数据恢复。

登记与资源引用在同一本机 registry 文件提交。缓存字节只在提交成功后删除；中断最多留下未引用缓存，不能使仍有效的登记指向已提前移走的本体。失败回执说明已停止进程或可能撤销的凭据，不声称恢复运行或重新授权。

## 数据导出与恢复

仅从已停止且无存活进程的选定实例读取状态，前后核对文件摘要。管理层只复制字节；数据格式 ID、版本、语义和可迁移性由模块定义。恢复要求精确模块版本及实际源码摘要匹配，并由用户明确确认业务兼容性；不自动迁移业务数据。

恢复先暂存全部目标数据，记录事务，再逐项替换状态目录。保留原数据快照；失败回滚，中断时阻止受影响实例启动或继续修改，并在资源界面提供恢复入口。恢复不换实例身份，不导入 Hub 日志或管理凭据，不启动程序。私人备份与公开数据集有不同用途；公开数据集需明确确认可分发。

当前有界制品传输支持二进制：单文件至多 8 MiB，总文件字节至多 64 MiB，制品 JSON 至多 96 MiB，单资源最多 4096 文件。社区发布请求至多 104 MiB，以容纳封面和证据；仍受请求期限及服务端容量限制。超过边界需拆分数据集或由模块使用独立数据传输能力，不改变 Hub 的通信类型。

## 管理 API

基础路径 `/manage/api/resources`。GET 返回当前修订、配置、本体、数据、实例和待恢复状态；POST 复用本机管理 CSRF 保护。接口不允许远端任意调用本机文件系统。

| 路径 | 用途 |
| --- | --- |
| `bodies/import` | 导入单本体、制品或包含 `index.json` 的本地静态本体集合 |
| `bodies/export` | 导出全局或选定实例本体及静态索引，去重依赖 |
| `sources/save` / `sources/remove` | 保存、启停或移除补齐本体使用的软件源，缓存与实例保留 |
| `profiles/import` / `profiles/export` | 保存外部配置 / 原样导出已保存版本 |
| `profiles/capture` | 捕获当前全局或局部配置并导出独立制品 |
| `profiles/retain` / `profiles/deactivate` | 设置保留集合 / 取消选定配置生效 |
| `profiles/prepare` | 从已配置来源补齐锁定本体 |
| `profiles/preview` / `profiles/apply` | 映射、审阅、应用配置 |
| `cleanup/preview` / `cleanup/apply` | 按保留根和依赖闭包清理登记与可选缓存 |
| `data/import` / `data/export` | 保存外部数据 / 导出停止实例的数据 |
| `data/preview` / `data/apply` / `data/recover` | 审阅恢复 / 应用 / 恢复中断事务 |

审阅有十分钟期限，最多保留 32 项。配置与数据各最多保存 256 个版本，本体池最多 4096 个版本，单配置至多 128 个逻辑实例。本地静态本体集合一次最多 128 个条目，本机登记与资源索引共同受 64 MiB 文件边界约束。保存、保留、取消生效、应用和清理都不会隐式启动业务程序。

本次不提供旧模块组制品的自动转换。需要发布新配置并引用独立本体。内部本机配置范围仍可使用现有分组管理结构，它不再是捆绑源码的公共下载资源。
