# 调用、注入与大体积通讯

程序自行定义信息、执行逻辑、信息来源与处理方式。wire 0.1 通过 welcome.features 协商 `directed-v1` 和 `blob-v1`，不能假定未知对端支持扩展。代码、规范与实际验收分别记录。

## 寻址与通道

目标是 `{principal, session?}`。principal 是认证后的稳定通讯身份：单身份接入对应 ACL bridgeId，凭据接入对应 credentialId；不采用 displayName、role、body 或程序注记。session 是 Hub 每次认证分配的随机 UUID，重连与重启不会重用；指定它只允许本次连接接收。省略 session 时，同 principal 下所有订阅了相应主题且获准接收的实例均可收到。枢纽不挑选一个“正确程序”，也不进行负载均衡或独占消费。

无 token 的受信回环接入仍标记 `authenticated:false`；上述身份地址不补出缺失的认证。principal 的公布、分发与业务认可由程序或部署方负责。推荐用程序自己的受信配置保存对端地址和主题，以对端 `welcome.principal` 核对；如程序自行通过发现主题交换地址，接收方须核对自己认可的通讯来源，不信 body 自报身份。Hub 数据面没有程序名册或业务发现帧；本机 status/manage 可列出当前接入主体和通道，管理注记仍是运维视图，不作为业务服务发现或授权依据。

mod 自主注册任意通道和主题并订阅。定向通讯同时要求主题权限与目标匹配；注册、向目标发送不会替目标创建业务处理器、订阅或启动程序。目标可以离线，稳定身份目标的信息留存后可由该身份后来抽取。未知预置身份默认拒绝；显式允许未列桥的回环测试模式可寻址合法未列身份，不保证它存在或会回应。

程序与 mod 桥仍支持 N:M。一个程序可使用多个 Bridge，多个程序也可共同使用一个桥；如何表示程序或协调共同凭据由这些程序决定。管理注记只是视图。

## 请求与回应

新帧 `request {target,topic,body,...}` 保存为受保护的请求。Hub 转交目标的相应订阅。目标程序自己查找、生成或调用所需信息，使用 `respond {requestSeq,body,...}` 回应。

Hub 以已接纳请求的 seq 查找原记录，验证回应者符合原目标（包括可选 session），从原记录推导返回 principal 和主题。回应者不能用 body、correlation、replyTo 或自报请求方修改返回地址。请求被清理后无法再用它生成可信回应。回应仍须具有该主题发布权限；请求方须具有返回主题订阅权限。所有原文正文仍按现有 bodyRaw 合同透传。

返回主题就是原请求主题，不能在 `respond` 中另指定内部回程主题。`requestSeq` 不自动把回应送入原调用连接；回应被接受后，仍由主题、可选 operations 和 target 条件匹配调用方的订阅。完整往返要求调用方与回应方均获准发布、订阅该主题。没有匹配订阅时，回应仍留存，由调用方后来抽取。订阅主题不会绕过 target 检查：第三方即使获准订阅该主题或 `#`，也不能旁观发给其他 principal 的定向请求与回应；同一 principal 的多实例共享身份权限，指定 session 才收窄到单次连接。

`published` 证明枢纽接纳。`delivery` 证明发生通讯投递。回应正文及是否成功由程序定义。请求、回应分别属于各自提供者，回应不会自动 release 原请求。

SDK `requestTo` 只等接纳；`respond` 只等回应接纳。`call` 是外部桥提供的便捷策略：先在原请求主题订阅 `operations:["response"]`，再请求，等待第一份符合可信 requestSeq 与提供者身份的回应，返回 `{request,response}`。调用方缺少此主题订阅权限时返回 `SUBSCRIBE_DENIED`。枢纽转发所有合法回应，程序可改用普通订阅处理多份、连续或迟到回应。本地 call 超时/断线只结束该等待，不取消业务操作、不删除请求、不禁止迟到回应。接纳结果不确定时不自动重发；业务幂等仍由程序处理。

可选 `subscribe.operations` 过滤 `publish/request/inject/response` 等协议通讯动作，用于桥的回应等待。它不限制业务信息种类；业务 `kind` 和通道仍无限定枚举。实时路由、历史抽取和最终投递检查同一过滤条件。

## 定向注入

新帧 `inject {target,topic,body,...}` 把信息交给目标程序的相应订阅。SDK `sendTo` 等接纳回执。接收程序自行决定写文件、更新自身状态、执行动作、拒绝或发另一条业务回执。Hub 不把“注入”解释成执行代码、修改上下文、调用工具或成功消费。

无消费者时继续留存。对第三方，即使其获准订阅 `#`，定向正文在实时与历史路径均不投递；同一凭据的所有实例共享通讯权限，精确 session 可以缩小本条目标范围。本机管理调试仍按现有可信回环范围查看全部通讯记录，不作为同用户隔离边界。

## 大体积附件

大对象是独立的磁盘通讯对象。消息日志只保留顶层 `attachments` 的可信描述符 `{id,size,sha256}`，不缓存对象全部字节。普通 body 上限和 4 MiB WebSocket 整消息上限继续适用。传输采用有界文本/base64 块，不用 WebSocket 分片伪装无限消息。

| 桥发送 | 接纳与行为 |
| --- | --- |
| `blob_begin {size,sha256}` | 分配服务端 UUID，按声明大小预约容量，归当前稳定 principal |
| `blob_status {id}` | 仅提供者查询已确认 offset 与状态，支持恢复 |
| `blob_chunk {id,offset,data}` | 按顺序有界写盘；旧范围重复必须与盘上字节相同 |
| `blob_commit {id}` | 长度完整后流式校验 SHA-256，成功才允许作为附件 |
| `blob_read {messageSeq,id,offset,length}` | 每次拉取一块；核验 retained 消息引用、订阅 ACL 与 target |
| `blob_release {id}` | 仅提供者解除保护，允许以后容量不足时清理，包含未完成上传 |

所有成功对象操作返回 `blob_result {operation,requestToken,...}`。对象 ID 本身不授予他人读取权。对象提供者可读取自己的 committed 对象；其他主体必须引用一条仍保留且可接收的消息。body 中写 ID 不等于可信附件。发布时只允许当前提供者引用自己的 committed 对象，不能将别人的对象扩大授权。

上传 SDK 支持文件与字节 async iterable；默认一块接纳后才发下一块。文件恢复先检查来源长度与 SHA-256，再从 Hub 已确认 offset 继续。流来源恢复时由程序提供从 offset 开始的数据。下载逐块写外部程序自己指定的本地文件，校验长度和 SHA-256 后才完成；默认不覆盖既有目标，失败保留 partial 供显式恢复。Hub 永远不根据程序传来的文件路径、文件名或 URL 访问外部文件或网络。

默认配置：单对象最大 1 GiB、总预约容量 2 GiB、最多 128 对象、每块 256 KiB；容量可配置，块最大 512 KiB。目录默认在 log.dir/blobs，显式 blobs.dir 可另设。对象必须用磁盘保存，即使 log.enabled:false 也不退化为整份内存；该模式下消息引用仍没有跨重启保证。普通消息日志容量与大对象容量分别检查。

预约包括完整与部分对象；容量不足明确拒绝新对象，只能清理提供者已经 release 的对象。不会按超时、读取、ACK、回应或断线解除保护。对象 release 与消息 release 独立；提供者应按自己的策略协调二者，允许已释放对象后来被清理时，旧描述符读取明确报不存在。上传完成后发布失败不自动删对象，提供者可重试发布同一对象。

新消息不能引用已释放对象。附件校验成功到消息追加结束期间使用短期通讯 pin 阻止容量回收，避免并发释放／新上传造成接受缺失附件；追加成功、失败或连接早退都会解除 pin。提供者仍可以显式标记 release，追加结束后其回收许可继续生效。pin 不表示消费或改变保留策略。

块落盘并 sync 后原子持久化确认 offset，再发收据。重启依据 offset 截掉未确认尾部；文件短于已确认 offset、损坏 metadata 明确拒绝启动。提交与下载做流式校验。单块丢失/收据不确定时可查 status，重复块一致则幂等，冲突拒绝。不承诺业务 exactly-once、断电后目录 rename 的 fsync 耐久、跨节点复制或对象加密。

慢接收者受到 WebSocket 出站缓冲字节上限；超过上限断连，留存数据保持可恢复。块拉取本身逐次进行，Hub 不主动把整个文件加入待发送队列。

## 验收

必须执行：真实外部程序的请求/回应与注入；一个程序两桥；无目标在线时后来抽取；共享凭据扇出及指定 session；第三方伪回应和 `#` 历史越权；新实例不接收旧 session 目标；回应超时不释放；大于单帧上限的数据往返与 SHA-256；中断/重启恢复、重复/冲突块、错误 hash、权限、预约拒新、只清理已释放对象、慢客户端出站边界与旧 wire 回归。

默认大文件验证样本先取 100 MiB，实际运行记录标明大小、分块和进程内存；接口限制可配置得更大，不将一个样本宣称为任意容量或长期高负载验收。示例程序只作为通讯验证夹具。

独立程序场景覆盖分布式上下文、委托调用、业务拒绝、多桥通断、目标离线、真实进程终止与 Hub 重启、容量和完整性。源码入口是 `examples/directed-transfer/`；可选 DSH 场景要求自己的已安装运行时，不进入默认 Node 测试。执行方法和范围见[验证说明](../verification.md)，不能用同进程 Bridge 冒充独立程序，也不能以样本推导任意容量。
