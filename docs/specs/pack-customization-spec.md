# 整合包来源、改装版本与直接保存

本规格描述 Launcher／参考 Runtime 的可选部署功能。Hub 继续只处理通信，不读取整合包版本、程序数据或改装历史。

## 版本与来源

`pack.version` 是唯一用于锁定和部署的整合包版本。更新原实例保持包 ID，并要求严格更高的版本；另存的新包不修改原实例。模块自身版本由模块作者维护。

包可声明 `lineage`，其内容被 `pack.lock` 中的包摘要覆盖：

```json
{
  "format": "world-hub.pack-lineage/v1",
  "kind": "customized",
  "base": {
    "id": "example.text-desk",
    "version": "1.0.0",
    "sourceDigest": "<64 位小写 SHA-256 来源修订>"
  },
  "revision": 1,
  "customizedAt": "2026-10-16T02:15:00.000Z"
}
```

`base` 记录首次来源，`revision` 记录后续改装次数；当前改装版本仍取 `pack.version`。空白工作台创建的包使用 `{ "format": "world-hub.pack-lineage/v1", "kind": "self-created" }`。自建包更新原 ID 保持自建身份，派生不同 ID 才记录原包为来源。

没有此声明的当前格式包显示“来源版本”；有改装声明的显示“来源基线”和“本地改装”；自建包显示“自建”。首次派生由经过检查的来源生成元数据，后续派生保留首次基线。草稿不能通过传入其他 `lineage` 将改装重新标为未经改装的来源。

来源声明与内容摘要不证明发布者身份、代码安全或“官方”资格。界面不根据任意包内字段赋予官方标记。导入已经改装的包也不意味着本机拥有其原始基线快照。

## 工作台直接保存

更新原实例在工作台完成“准备差异 → 审阅 → 应用”，无需转到存储页粘贴候选路径。准备候选不表示更新已生效；只有实际事务提交成功才显示保存成功。

应用必须绑定目标实例、当前源码与锁、候选内容、解释器和停止状态。预览后源码、数据、候选或环境变化需要重新审阅。实例运行中不能直接覆写；用户须先明确停止并等待所属进程确认退出。保存不自动启动，旧的执行授权失效。

审阅展示版本、模块增删和替换、公开参数、主题、权限、能力接线与启动计划等差异。来源于运行装配快照时，还须核对原运行 ID、装配修订和实际安装基线；不能把另一个实例的草稿套到当前实例。

## 私有数据与事务

直接保存默认原样保留仍在组合中的组件数据及 Hub 持久数据。新增成员使用新状态；移出成员的数据保留于事务快照。字节保留不等于业务兼容，也不表示 Hub 理解或迁移了程序的数据格式。更换程序后，数据是否可用由该程序验证；需要自定义迁移时使用独立的明确迁移流程。

修改前自动保存当前软件、实例身份和持久数据的私有快照。快照与事务使用原地升级的维护锁、暂存、校验、提交和恢复机制。备份失败不继续提交，部分提交失败恢复原状态；无法确认恢复时保留事务并阻止进一步启动。多目录提交不宣称文件系统具备跨目录的单次原子替换能力。

持久数据快照包含程序数据和 Hub 日志、对象及管理状态；每个程序数据目录顶层的 `tmp`、监督者运行记录、`runs` 和生成的控制凭据不在恢复范围。程序应将需要保留的业务状态放在其他持久路径。具体文件与大小边界沿用[升级快照规则](../ecosystem/upgrade.md)。

私有快照不包含在可分享的导出包中。其内容可能含个人数据与程序保存的秘密，应留在实例私有目录。

## 历史与恢复

存储页列出实际保留的改装事务和可恢复快照。只有本机确实保存了初始未改装来源的快照，才能提供“恢复来源基线”；缺少该快照时明确表示不可用，不从版本文字伪造恢复能力。

恢复同样要求停止、重新预览并确认。恢复软件、配置和该快照内的程序／Hub 数据，可能替换改装后的新数据；应用前先保存当前数据快照。恢复不启动程序，之后仍须重新审阅。历史恢复不能撤销已发送的信息、远程 API、设备操作或其他程序的外部状态。

## 接口与验证

`POST /api/instances/:id/customization/preview` 准备锁定候选及停止状态下的差异审阅；`POST /api/instances/:id/customization/apply` 只接受该审阅的标识和明确确认。`GET /api/instances/:id/customization/history` 返回实际事务与基线可用性。`POST /api/instances/:id/customization/restore-preview` 通过事务 ID 预览恢复，`POST /api/instances/:id/customization/restore` 接受该审阅及明确确认，复用回退事务。前端不能指定任意快照路径。

整合包与全局 Hub 的启动计划统一在工作台的“启动计划”页编辑，并经审阅保存为新的本地改装版本；不能在后台直接改写已安装的 `pack.json`。成员选择、明确前置、精确执行顺序与失败处理分别编辑。“恢复默认”只将本次草稿的计划还原到当前已保存版本，保留新增模块及其他装配设置；它不恢复上游来源基线，也不直接改运行状态。详见[启动计划](startup-plans-spec.md)。

验收包含首次和重复改装、来源保留、自建包、模块增删、原样数据保留、内容变化拒绝、运行互斥、自动快照、恢复与重新授权，以及中英文界面和实际发行 ZIP。
