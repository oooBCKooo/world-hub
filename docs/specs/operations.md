# 接入管理与操作体验

wire 为 0.1。本机管理操作遵循[定位与边界](boundaries.md)，不改变程序、mod 与 Hub 的职责。

## 工作台操作

从 `/manage` 的“通讯工作台”进入。工作台使用自己的实际 mod 收发，接入管理通过现有本机管理接口操作通讯状态；注记不参与身份、权限或寻址。

- 每个通讯主体各有本页内存中的未保存注记草稿。切换主体和刷新状态保留草稿；保存只提交当时的完整列表，提交后继续输入的内容仍属于未保存草稿。可单独丢弃当前主体的本页草稿，不修改已保存注记。最多64个主体，达到上限明确提示；刷新页面后草稿消失，token与业务正文不随草稿持久保存。
- 管理请求有8秒本地等待期限，后到的旧刷新不能覆盖新的状态。显示快照取得时间及是否失效；请求失败后保留草稿并禁用陈旧管理动作，用户重新刷新核对。超时表示本地等待终止，不保证先前提交未生效，也不自动重发。
- 收发记录可按方向与帧文本筛选。筛选仅改变本页显示，导出包含全部当前保留记录。新帧不会收起仍在保留范围内的详情或抢走阅读焦点；受原有160条／2MiB记录、40条／1MiB投递列表上限约束，轮出不是Hub删除或消费确认。
- 断连后的身份、session、握手限制、订阅及投递明确标为上次连接。历史投递的ACK填入入口失效；再次连接需要用户操作，不自动恢复订阅、重发、ACK或释放。

管理快照只反映取得时的通讯状态，不证明程序在线或业务成功。不同浏览器的并行注记编辑仍可能互相替换完整列表，没有提供跨页面编辑锁或业务审批。

## 通讯配置与生命周期

配置加载在打开存储前验证日志开关及段容量、ACL容器与条目、权限数组及每条主题过滤器等通讯字段。非法配置指出字段并拒绝，不把非法 `#/private` 自动改成宽权限。未填写的有效默认值、任意合法主题和载荷正文继续保持原合同；原入口和包级只读检查使用同一配置验证。

WebSocket upgrade 附带首帧时，先注册连接消费者，再解析已接收缓冲，避免一次TCP写入中的hello或关闭通知在消费者建立前消失。拒绝后的连接不再派发缓冲数据。这不执行任何程序载荷。

桥的诊断观察器抛异常或异步拒绝时，不应破坏已成立的连接、造成未处理拒绝或混淆真实通讯错误。观察诊断和程序的delivery处理是不同回调；后者的成功／失败及ACK策略保持原意。

## 验证与交付

`npm test` 包含操作状态、配置、管理资源、浏览器桥、TCP 传输及 JS 桥回归。静态模块由精确资源白名单提供，受本机访问、Host／Origin 和 CSP 约束。执行方法与证据范围见[验证说明](../verification.md)。

分发包默认只启动通讯枢纽和管理界面，外部程序自行安排部署、业务、状态、重试和释放。跨 Hub 文件游标按部署及桥实例隔离，见[接入材料](../onboarding.md)。
