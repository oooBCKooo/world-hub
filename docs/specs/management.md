# 枢纽本机管理 API

本规范约束非界面管理 API 范围及验证要求。页面、渲染与浏览器交互由独立 World Hub UI 项目负责，不随 Hub 交付。Hub 的 `/manage` 返回 404；API 不读取页面文件。文中涉及显示的要求属于外部客户端解释，不能成为核心启动依赖。

要求本身不充当实际执行证据，测试方法见[验证](../verification.md)。

管理继续遵守[定位与边界](boundaries.md)、[通讯契约](protocol.md)和[可靠性与访问边界](reliability-access.md)。


## 无界面调用

GET `/manage/api/state` 返回当前管理快照和 `csrfToken`，GET `/manage/api/programs` 与 `/manage/api/resources` 返回实例及资源。写请求须带 `Content-Type: application/json` 和 `X-Management-Token: <当前 csrfToken>`，保持同源或无浏览器Origin的本机脚本调用。API只接受回环、精确本机Host和正确端口，不通过 `Access-Control-Allow-Origin: *` 放宽访问。

```powershell
$hubBase = 'http://127.0.0.1:8790'
$state = Invoke-RestMethod ($hubBase + '/manage/api/state')
$headers = @{ 'X-Management-Token' = $state.csrfToken }
Invoke-RestMethod ($hubBase + '/manage/api/bridge') -Method Post -ContentType 'application/json' -Headers $headers -Body '{"key":"my-program","action":"pause"}'
```

`/manage/api/resources` 的子操作覆盖本体导入导出、配置捕获/导入/审阅/应用、数据备份/恢复以及按保留引用清理，见[资源规范](module-resources.md)。审阅和应用必须用当前reviewId，不能以直接覆盖文件代替事务。外部UI在自己的进程提供页面及固定目标代理，保留令牌；不导入Hub内部源码。

## 1. 目标

在本机 `/manage/api/**` 提供非界面 JSON API，通过通用管理方法 查看 Hub 的通讯身份、连接、枢纽桥注册通道、订阅与近期通信记录，并管理通讯主体的接入。它管理的是十字路口本身的连接与观测，不运行连接到十字路口的程序业务。

所有示例都是验证 Hub 的外部对端。它们的上下文、面板、harness 或模型接口不进入 Hub，也不要求其他程序沿用示例组织方式。管理界面不需知道载荷属于系统提示词、传感器读数、命令还是未来的新种类。

数据面仍采用 **wire 0.1**。管理面采用通用管理方法和观测事件，不增加 `run_program`、`run_harness`、`get_context` 等业务操作，也不建立业务通道或载荷种类枚举。

## 2. 可以查看的内容

管理 API 与界面可以呈现以下通讯元数据：

| 对象 | 可观察内容 | 不能据此推导的内容 |
| --- | --- | --- |
| Hub | 全局 Hub 的运行元数据、接入限制与有界通讯计数 | 外部程序的业务状态 |
| 通讯主体 | 单 ID 主体或 credential 主体的标识、接入暂停状态 | 程序用途、运行位置或执行资格 |
| 当前连接 | Hub 分配的连接标识、当前实例身份、声明名称和已连接时间 | 外部程序是否仍运行，或整个程序是否仅有这一连接 |
| 通道与订阅 | 枢纽桥实际登记的主题、发收方向、过滤器、确认与扫描进度 | 载荷 Schema、业务 handler、上下文是否完整 |
| 通信记录 | 序号、时间、主题、来源、关联标识、大小等 envelope 元数据 | 接收程序已看到信息、业务已经完成 |
| 近期信息流 | Hub 实际接纳发布和执行投递动作所留下的有界样本 | 全部历史、全部传输路径、每次接收与业务效果 |

列表与信息流以通讯元数据为范围；用户选择序号时可按需读取保留中的原始消息，以安全文本显示原文，包括正文。界面不解释 `body` 的业务语义，不根据载荷生成业务控件，不执行载荷、任意脚本或其中声明的动作。桥名称、主题和用户注记同样以安全文本呈现。

未来主题、未连接的主体和未找到实时生产者的通道都可以显示。无连接只能标为“未连接”；外部程序的运行状态应显示为“未知”，不能标为“已停止”。

连接的 `declaredId`、`role`、`displayName` 是声明或诊断信息。它们不能替代 Hub 的真实通讯主体，也不能因文字包含 `context`、`ui`、`harness` 或其他名称而获得特殊管理资格。

## 3. 三项接入管理操作

管理请求明确选择主体类型或本次连接标识，避免把同名的不同对象混为一项操作。

| 操作 | Hub 行为 | 持久性与显示含义 |
| --- | --- | --- |
| 暂停主体接入 | 保存该稳定主体的暂停状态，断开它当前的连接，拒绝它后续接入 | Hub 重启后仍暂停；不表示外部程序被停止 |
| 恢复主体接入 | 保存移除暂停限制的状态，允许枢纽桥按自身策略重新连接 | 仍须通过原有认证、主题 ACL 和容量检查；不保证立即连上 |
| 断开本次连接 | 关闭所选当前连接，不保存主体暂停限制 | 枢纽桥可以自动重连；过期连接标识不能误断一个后来出现的新连接 |

**单 ID 主体**指采用单桥身份接入的稳定主体。**credential 主体**指采用配置凭据接入的稳定主体；其当前连接可能表现为多个独立实例身份。暂停 credential 主体影响该凭据下的全部当前实例和后续实例，不只影响界面当前选中的某个声明名称。恢复不扩大该凭据的 ACL。

暂停与恢复属于 Hub 的通讯接入控制。它们不删除已接纳的记录、不重置消费游标、不伪造 ACK、不撤销已发生的业务操作。恢复后的历史抽取仍执行原有保留范围、过滤器、游标、确认和缺口规则。

暂停操作应在管理状态持久保存成功后报告成功并执行断连。状态写入失败须明确失败，不能宣称已持久暂停。重复暂停或恢复同一主体应具有一致结果；管理动作自身不能触发外部业务重做。

## 4. 程序与桥的关系仅作视图注记

用户可填写程序名称、注记及它与通讯主体的关联关系。该关联支持 **N:M**：一个程序可关联多座桥，一座桥也可被标注为服务多个程序。程序不必与桥一一对应，也不必各自占用一个独立进程。

这些注记仅帮助阅读拓扑。它们不参与 hello 认证、主题授权、路由、留存或执行决策，不证明程序已运行，也不证明该关联已经由程序自行确认。删除或修改注记不改变桥的通讯行为。

界面不启动、停止或重启外部程序，不向外部程序发送停止命令，不决定程序本地接口，也不要求枢纽桥使用某种宿主、CLI、浏览器、插件或 IPC 形态。

示例启动器使用 IPC 向它自己拥有的本地子进程表达停止意图，是参考程序的生命周期机制。它不是 wire 协议，也不是所有桥或所有程序必须采用的接入条件。

## 5. 管理状态与访问边界

`management.json` 保存稳定主体的暂停状态和用户视图注记，采用原子持久写入。默认跟随有效日志目录，`--log-dir` 同时隔离默认管理设置；`management.stateFile` 可指定独立位置。未创建过管理状态时使用空暂停集与可选 `management.annotations` 初始注记；已有用户文件优先。文件无法解析或结构无效时，Hub **拒绝启动**，不能静默恢复为空并意外开放已暂停的接入。即使消息日志关闭，管理设置仍单独持久保存。

通用通讯观测 API 只返回所需元数据，不返回 ACL token、hello token 或包含这些值的配置原文。credential 标识可以用于选择稳定通讯主体，但不等于向界面公开凭据秘密。用户主动授权独立外部程序的专用接入操作可返回该程序所需的私有连接资料；社区、模块组导出和通用观测不包含这些资料。

管理 API 仅接受回环访问，并校验合法的本机 Host。浏览器管理变更校验同源 Origin 与 CSRF token；本机 API 客户端即使没有 Origin，也须满足 Host 与管理请求的 token 校验。拒绝跨来源变更、非法 Host、非回环请求和无效 token。

这是本机管理入口，不是公网控制服务，也不提供本机不同用户或不同应用之间的账号隔离保证。数据面监听地址与管理面访问范围分别处理；数据面允许远端枢纽桥接入，不意味着远端能调用管理 API。

## 6. 留存与观测边界

信息的留存许可仍由提供者策略决定。管理界面不替提供者发送 `release`，不提供强制删除未释放信息的操作，也不因为提供者离线、被暂停、凭据移除或界面标注了程序关系而清理其记录。

当前参考日志容量是全局容量。最旧段仍受保护时，`LOG_CAPACITY` 可以拒绝所有提供者的新发布；这项限制不会因为新增管理界面而变成按提供者隔离。界面应诚实显示容量拒绝及保护状态，不把“有人读取过”或“连接已断开”视为删除许可。相关合同仍见[可靠性与访问边界](reliability-access.md)。

留存对话框显示最旧段未释放主体及序号、未使用段位、活动段距轮转目标、附件预约／剩余／可回收量和本进程 gap 落盘失败数。它们是只读通讯观测，不授予强制删除或业务管理权；未知历史身份显示未知，可回收预约不等于已经删除，目标剩余字节不等于精确可写容量。启动 ready、`/status.storage` 与管理摘要共享数据，详见[部署](../deployment.md)。

信息流来自真实 Hub 接纳、投递与管理动作的观测记录，采用有界近期样本。投递动作最多证明 Hub 执行了该次通讯动作，不证明接收程序已收到或业务已完成。ACK 表示该订阅提交了通讯消费确认；它不证明工具、渲染或其他程序业务成功。样本缺失、分页范围和记录保留范围应分别说明，不能把近期图当作完整历史。

## 7. 验证要求

### 同一界面中的本机模块管理

独立 Launcher 已取消。本机管理 API 的模块部署辅助层可管理用户明确导入的受管子进程；其源码、解释器、配置、启动计划与进程所有权由该辅助层负责，Hub Core 和 wire 不读取模块或模块组清单，也不执行业务。仅有桥连接或程序注记的独立应用仍是不可观测的外部对端，不能凭注记启动、接管或终止。

工坊只获取 `module` 与 `module-group`。索引摘要、制品摘要和网络策略绑定同一次选择，索引变化后须重新检索。目录、ZIP 或 JSON 制品均先校验、审阅，再注册为停止状态；下载和导入不构成执行授权。单模块消费者明确选择已安装的能力提供者；模块组将组内引用映射到新的独立实例身份，成员共用本机 Hub，不携带 Hub、身份凭据或运行数据。组导出需要明确发行版本与再分发确认，保留成员各自版本；社区拒绝用不同内容覆盖已发布的同一版本。

启动组计划只运行被选中的成员，并遵循依赖和明确顺序。关闭本机管理服务时只停止它实际拥有的子进程，不按历史 PID 终止外部应用。此处的受管实例状态与上文仅凭通讯观察的“未知”状态分开呈现。

### 受管模块与模块组的版本事务

本机部署辅助层支持模块与模块组的原位升级、选择较旧发行版本降级，以及回退到已完成事务之前的版本。Hub Core、数据面协议与业务载荷不参与版本决策。模块组只引用本机 Hub 上的独立实例，不创建组专属 Hub；已退役的整合包与模板不属于此接口。

- 目标模块或来源明确的模块组必须保持发布 ID 相同，目标版本与来源文件摘要独立核对，拒绝同一模块版本对应不同源码。模块组通过配方中的逻辑成员 ID 映射已有实例；已有成员保留身份，新增成员分配新身份，移除成员只脱组，不注销或停止实例。原生配置 API 不接受 `directory` 源码替换，源码必须经版本审阅，不能绕过版本历史。
- 修改源码的已有实例必须处于本机管理器确认的停止状态。不能根据历史 PID 接管或终止外部进程，也不因更新组而自动停启其他组、消费者或被移除的成员。
- 更新审阅明确区分公开配置策略 `preserve`／`author` 与私有数据策略 `preserve`／`fresh`。回退恢复所选事务前的源码及公开配置，私有数据选择 `preserve` 或 `restore`。所有应用均需确认代码、权限、接线及未验证的数据兼容性。
- 保留既有 `programId`、通讯主体、私有凭据和默认当前状态目录，不把状态解释为业务数据 Schema。`fresh` 保存原状态快照并建立空目录；`restore` 覆盖当前状态为所选事务前的快照，包括当时目录不存在的情况。不能撤销实例目录之外的数据、Hub 历史、其他模块状态和外部副作用。
- 审阅列出受影响的共享组和已登记消费者。不得允许候选提供者移除仍被消费者绑定的准确契约，也不得将缺失、自绑定或不兼容的提供者写入配置。公开配置保留同样须满足目标版本声明；版本号不作为业务兼容性证据。
- 审阅有效期十分钟；应用重新核对目标修订、候选源码、解释器、状态快照和其他实例／组环境。数据或接线在审阅后改变时拒绝应用，不沿用旧授权。
- 本地注册表与源码切换作为带私有日志的事务执行，失败时恢复原注册及源码／状态。无法完成恢复时保留快照和中断标记；即使尚未来得及写入实例标记，事务日志也须阻止受影响的启动、注销及配置变更。恢复核对快照元数据摘要、身份和当前源码／状态仍属于本次切换的前后状态，拒绝覆盖外部改动；`preserve` 数据策略恢复时也不得覆盖后续状态。事务已提交而标记清理失败时只补清理，不回滚已提交的版本。
- 历史、源码及状态快照在本机私有目录持久保存，重启后仍可读取与恢复；公开概览和错误不返回身份 token、私有配置或状态文件正文。当前历史不自动清理，容量不足或快照超限须在切换前拒绝。

版本 API 均沿用回环 Host、同源及 CSRF 边界。`collection` 为 `modules` 或 `groups`，`id` 为现有本机实例或组 ID：

| 方法与路径 | 输入与用途 |
| --- | --- |
| `GET /manage/api/versions/{collection}/{id}` | 读取 `current`、目标修订、已提交 `history` 及 `recoveryRequired`；不是可下载版本索引 |
| `POST /manage/api/versions/{collection}/{id}/preview` | `path` 指向目标目录、ZIP 或 JSON 制品；`expectedRevision` 使用概览修订；可选 `configurationPolicy`、`dataPolicy`；无来源本地组须明确 `establishOrigin: true` |
| `POST /manage/api/versions/{collection}/{id}/rollback-preview` | `transactionId` 为属于该目标的已提交事务，附当前 `expectedRevision` 和回退 `dataPolicy`；恢复该事务发生前的版本 |
| `POST /manage/api/versions/{collection}/{id}/apply` | 提交刚审阅的 `reviewId`、`accepted: true` 与 `dataAcknowledged: true`，不接受跳过审阅的直接路径替换 |
| `POST /manage/api/versions/{collection}/{id}/recover` | 提交中断 `transactionId` 和 `accepted: true`，恢复该事务或清理已提交标记，保持模块停止 |

版本验收使用真实本机 HTTP 管理 API 和独立 Node 子进程，至少覆盖原位升级／降级／回退的身份及数据策略、组成员增减、共享实例影响、合同破坏拒绝、修订／源码／状态变化拒绝、运行实例不被终止、注册表写入失败、中断恢复、重启后的历史和公开响应无秘密。实际执行结果见 `tests/conformance/management-versions.test.mjs` 的本次测试输出，不能将要求表述当作执行证据。

### 常驻与按需执行策略

本机部署辅助层保存实例级 `executionPolicy: {mode, idleTimeoutMs, allowedCallers}`。`mode` 为 `resident` 或 `on-demand`；空闲时间为 1000 至 86400000 的整数毫秒，默认 60000；调用者为去重、已登记的其他实例 ID，默认无授权。多个组引用同一实例时共享策略。

作者可在 `deployment.json` 声明可选 `executionDefaults: {mode, idleTimeoutMs?}`，其中 `mode` 必填，取值及空闲时间范围同上。模块组成员的 `configuration.executionDefaults` 可覆盖模块默认值。新实例依次选择组成员默认值、模块默认值或内建 `resident`／60000 毫秒；选中对象省略空闲时间时使用 60000，不继承另一来源的时间。导入审阅须显示最终 `executionPolicy` 和默认值来源，导入后保持停止且 `allowedCallers: []`。作者默认值禁止 `allowedCallers`、调用者实例 ID 和其他启动授权字段，不因同组引用而自动授权唤醒。

用户保存的实例策略覆盖导入默认值。模块组导出只将成员当前策略的 `mode` 与 `idleTimeoutMs` 写为可分发 `configuration.executionDefaults`，不序列化本机调用授权。此规则不使本机策略或身份成为可移植权限。

编排只执行启动计划中 `enabled: true` 且策略为 `resident` 的成员，审阅与结果列出跳过原因。保留原 `enabled`、完整 `startupOrder` 与 `after`；前端读取计划不得改写这些值。添加依赖不等于授权启动。按需前置没有就绪时阻止依赖它的步骤，不自动提升为常驻或拉起依赖。独立手动启动仍可用。

| 方法与路径 | 输入与用途 |
| --- | --- |
| `POST /manage/api/programs/{id}/execution-policy` | 当前 `executionPolicyRevision` 作为 `expectedRevision`，以及完整 `policy`；校验版本守卫后原子保存，不启停程序 |
| `GET /manage/api/execution/status` | 读取生命周期管理器可用状态、每个实例的自动启动所有权、手动保持、活动／结果未知租约数和空闲停止时间；不返回租约 ID、token 或私有配置 |

以上管理 API 沿用回环 Host、同源与 CSRF 边界。策略变化进入配置修订、版本及启动审阅的指纹。原位版本升级、降级和回退保留已有实例当前的完整本机执行策略，包括采用作者公开配置时；不从历史或作者制品恢复旧调用授权。组更新新增的成员按新实例默认值规则初始化。

生命周期管理器使用普通认证枢纽桥及自己选择的控制主题。受管实例启动审阅公开该控制描述符，私有运行配置提供 `lifecycle`；其权限不加入业务主题映射。管理器惰性启用，只接收自启用后的新定向请求，依据 Hub 提供的可信 `fromPrincipal` 映射已登记调用者。`acquire` 只在目标按需策略明确允许调用方、源码及运行审阅仍有效时启动受管程序；`renew`／`release` 只接受持有者的租约。所有操作再次检查授权和版本恢复守卫，不能接管外部进程或通过业务正文改变权限。

并发激活在本机管理队列中去重，最多 128 份租约、每调用者和每目标各 32 份；排队激活也占额度并阻止空闲停止。管理器返回就绪目标身份，由调用方用自己的桥完成原业务请求。业务载荷不经过生命周期代理。JavaScript 提供 `world-hub/lifecycle` 的 `callManaged`、`acquireManagedLease`、`withManagedModule`；其他语言使用同一控制契约，详情见 [客户端文档](../../sdk/javascript/LIFECYCLE.md)。普通 wire 调用不隐式激活程序。

续租和完成通知独立于耗时的进程启动队列；控制订阅分别回应并确认各请求，不让一个慢启动阻塞其他任务的续租。此控制契约采用自愿的短期留存：客户端收到控制回应后释放自己的控制请求，管理器在控制回应接纳后释放自己的控制回应。它们均只释放自己提供的控制序号，不释放业务信息、不提供 Hub 强制清理。控制结果丢失时保守保留未知任务，不自动重发业务请求；首次续租失败后停止自动续租并报告，避免断线期间无限新增控制记录。

管理器只自动停止自己按需启动的同一 owned handle 与 `runId`。用户手动启动固定该次运行；改变策略或有结果未知任务不会擅自终止。有效任务租约持续保护运行，全部明确完成后开始空闲计时；租约到期、通讯超时、断线或不确定释放只标记为结果未知，不推导业务完成。用户明确停止该次运行后清除其租约；旧租约不得影响新进程。停止前在同一队列内重新核对所有权、策略、租约、空闲时间、版本守卫与关闭状态。

验收使用真实独立 Node 调用者与提供者，覆盖编排跳过、授权与冒用拒绝、并发一次启动、长任务保护、完成后空闲停止、再次唤醒、超时未知保留、手动保持、策略 CAS／持久化／失败恢复和普通通讯不变。结果以 `tests/conformance/management-execution.test.mjs`、`execution-policy.test.mjs`、`demand-lifecycle.test.mjs` 的本次执行为准。

### 恢复默认接线

“恢复默认接线”属于本机部署辅助层，Hub Core 与 wire 不读取作者配方或选择业务提供者。接线模式顶部提供入口，按明确的全部实例、模块组或单实例范围先预览、再接受审阅。

- `all` 范围中，具有来源配方的组成员采用组作者默认值，其余实例采用本模块 `deployment.json`；没有发布来源的本地组不虚构作者配方。`group` 明确采用该组配方，列出共享实例会影响的其他组；`module` 明确采用模块自身默认值，而非组配方。所有审阅均显示每个实例的默认来源以及变化前后的主题、桥权限和能力绑定。
- 本地组保存受校验的 `wiringBaseline`，包含来源 ID、版本、逻辑成员及其模块 ID、版本与接线，不包含设置、启动计划或私有数据。初次导入与组版本更新均从已校验的作者制品建立；即使版本更新选择保留改装配置，也保存新版本的作者配方。普通组编辑不能覆盖配方；版本回退随事务恢复相应组配方。
- 已有来源组缺少配方时，预览返回 `missingGroupSources` 并阻止应用；用户明确选择来源 ID、版本与当前成员匹配的目录、ZIP 或 JSON 制品后，审阅可建立该配方。不得根据当前改装、同名版本缓存或列表顺序推测默认值。来源中的必要提供者不在当前组或未登记时拒绝恢复，不重新加入成员，不下载或升级源码。
- 全部范围中共享实例的多组配方冲突必须列明并阻止应用；明确选择组范围时采用所选组配方，并列出其他共享组和已登记消费者。逻辑成员与实例的映射必须结合当前组成员集合核对，不能将历史累计映射中的脱组实例重新加入。
- 单模块默认连接使用准确的模块身份、版本、能力和主题别名权限。唯一兼容实例可解析，多个兼容实例须用户明确选择，缺失则阻止；不根据标题、运行状态或列表顺序猜测。批量解析使用本批候选提供者恢复后的主题。作者没有指定默认目标的普通能力绑定保留合法的现有选择；最终全部能力引用仍须满足已登记实例声明。
- 只修改 `topics`、`bridges`、`bindings`，不修改公开设置、源码、版本、解释器、身份、私有状态或任意启动计划。发生实际接线变化的实例必须确认停止且无活动受管进程；不变的运行实例可保持运行。此操作不停止或启动任何进程，不暂停本机 Hub。未知进程所有权和待恢复版本事务不得被绕过。
- 审阅最长十分钟，绑定源码、身份摘要、配置、分组、启动计划、提供者候选与当前进程所有权；应用和撤销旧权限后重新核对。公开响应不含 token、身份原文或私有状态。失效或有阻塞的审阅不能应用，不接受跳过审阅的直接覆盖。
- 批量应用在同一管理队列内执行，撤销变更实例的旧凭据后，一次保存新接线和本次建立的组配方。提交失败恢复整批原注册表与组配方；已经撤销的凭据保持撤销并明确报告，不能恢复旧权限或误报部分成功。

以下 POST 均沿用回环 Host、同源与 CSRF 边界：

| 方法与路径 | 输入与用途 |
| --- | --- |
| `POST /manage/api/wiring/defaults/preview` | `scope` 为 `all`、`group` 或 `module`；后两者附 `targetId`。可选 `groupSources: {groupId: path}` 补充缺少的准确作者制品，`connectionSelections: {programId: {connectionId: providerId}}` 选择有歧义的默认连接 |
| `POST /manage/api/wiring/defaults/apply` | 提交 `reviewId` 和 `accepted: true`；仅应用刚审阅的范围和来源，不接受新的配置覆盖 |

验收覆盖真实 HTTP 批量恢复与设置／身份／数据／源码／启动计划保留、组配方优先及重启持久性、新版本作者配方与保留改装的区分、来源补录、准确默认提供者与歧义、共享组冲突、源码／配置／分组变化失效、运行实例不被停止且不变实例继续真实通讯、注册表失败整批恢复、CSRF 及版本恢复守卫。实际执行结果见 `tests/conformance/management-wiring-defaults.test.mjs` 的本次输出，不能把验证要求视为已执行证据。

### 受管实例与整组卸载

卸载属于本机部署辅助层，不能改成 Hub Core 的业务或路由规则。模块与模块组均先审阅、再明确确认注销；仅删分组继续使用 `POST /manage/api/groups/{id}/remove` 和准确 `expectedRevision`，不停止或注销成员。“整组卸载”必须采用独立的审阅入口，不能借用仅删分组而让用户误以为成员已卸载。

- 单实例注销自动清理所有组中的该实例引用、全局及受影响组的启动计划顺序和前置引用。若其他保留实例仍绑定该提供者，必须阻止注销，不得自动删改消费者能力绑定。
- 整组默认选择仅由本组持有的安全成员，保留其他组共享实例及被保留消费者依赖的提供者；保留范围计算到传递闭包，包含依赖环。用户可缩小注销选择；选择中包含仍共享或被保留消费者依赖的实例时，审阅应列明阻塞原因，不能通过应用。
- 审阅返回每个成员的版本、选中状态、真实所有权、共享组、消费者、保留目录、需要停止的实例和计划清理项，不返回 token 或私有配置。审阅绑定当前可读源码摘要、身份、接线、分组、计划和进程所有权，最长十分钟；应用前和停止选定进程后重新核对，不沿用过期授权。纯健康观察时间更新不使审阅失效；源码缺失或不可读时记录其不可用状态，仍可注销登记，不重建、执行或删除该目录。
- 只在 `stopOwned: true` 且明确接受审阅后停止当前拥有的选定子进程。无所有权的历史 PID、未知状态或未完成清理不得被终止或强制注销；不停止保留实例或本机 Hub。相关版本事务未恢复时不能注销或改动受保护分组。
- 本次选定实例、组引用和全局计划的注销采用一次最终注册表提交。写入失败恢复全部登记、身份映射、分组和计划，不允许半组注销；已经授权并停止的进程保持停止，已撤销的凭据不能未经重新启动审阅恢复。停止或撤销凭据失败时保留全部注册并明确失败。
- 注销撤销选定实例的通讯凭据，但源码、实例状态、身份文件和版本事务目录原位保留。不能将保留文件描述为已自动建立恢复功能；版本历史依赖现存登记，注销实例后不能直接从版本事务回退。注销不清理 Hub 历史、不代发 release、不撤销外部副作用。

`collection` 为 `modules` 或 `groups`，`id` 为现有本机实例或组 ID，以下 POST 沿用回环 Host、同源与 CSRF 边界：

| 方法与路径 | 输入与用途 |
| --- | --- |
| `POST /manage/api/uninstall/{collection}/{id}/preview` | 默认安全范围审阅；可选 `programIds` 为目标范围内显式选定的实例 ID，组可传空数组只删除组 |
| `POST /manage/api/uninstall/{collection}/{id}/apply` | `reviewId`、`accepted: true` 及明确的 `stopOwned`；阻塞审阅不能应用，状态变更后重新审阅 |

验收覆盖真实 HTTP 旧单实例路径遇组成员失败的根因、审阅注销后的引用清理与文件保留、能力消费者阻止、共享与传递依赖闭包、真实子进程只停止选中成员且保留共享成员继续通讯、过期审阅、无效 CSRF、版本恢复和未知所有权守卫、提交失败全组登记恢复及已停止进程不复活。具体执行见 `tests/conformance/management-uninstall.test.mjs` 本次测试输出。
