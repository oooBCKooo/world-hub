# 枢纽通讯管理界面

本规范约束通用管理面范围及验证要求。

要求本身不充当实际执行证据，测试方法见[验证](../verification.md)。

管理继续遵守[定位与边界](boundaries.md)、[通讯契约](protocol.md)和[可靠性与访问边界](reliability-access.md)。

## 1. 目标

在本机 `/manage` 提供静态管理界面，通过通用管理 API 查看 Hub 的通讯身份、连接、mod 注册通道、订阅与近期通信记录，并管理通讯主体的接入。它管理的是十字路口本身的连接与观测，不运行连接到十字路口的程序业务。

所有示例都是验证 Hub 的外部对端。它们的上下文、面板、harness 或模型接口不进入 Hub，也不要求其他程序沿用示例组织方式。管理界面不需知道载荷属于系统提示词、传感器读数、命令还是未来的新种类。

数据面仍采用 **wire 0.1**。管理面采用通用管理方法和观测事件，不增加 `run_program`、`run_harness`、`get_context` 等业务操作，也不建立业务通道或载荷种类枚举。

## 2. 可以查看的内容

管理 API 与界面可以呈现以下通讯元数据：

| 对象 | 可观察内容 | 不能据此推导的内容 |
| --- | --- | --- |
| Hub | 本机 Hub 的运行元数据、接入限制与有界通讯计数 | 外部程序的业务状态 |
| 通讯主体 | 单 ID 主体或 credential 主体的标识、接入暂停状态 | 程序用途、运行位置或执行资格 |
| 当前连接 | Hub 分配的连接标识、当前实例身份、声明名称和已连接时间 | 外部程序是否仍运行，或整个程序是否仅有这一连接 |
| 通道与订阅 | mod 实际登记的主题、发收方向、过滤器、确认与扫描进度 | 载荷 Schema、业务 handler、上下文是否完整 |
| 通信记录 | 序号、时间、主题、来源、关联标识、大小等 envelope 元数据 | 接收程序已看到信息、业务已经完成 |
| 近期信息流 | Hub 实际接纳发布和执行投递动作所留下的有界样本 | 全部历史、全部传输路径、每次接收与业务效果 |

列表与信息流以通讯元数据为范围；用户选择序号时可按需读取保留中的原始消息，以安全文本显示原文，包括正文。界面不解释 `body` 的业务语义，不根据载荷生成业务控件，不执行载荷、任意脚本或其中声明的动作。桥名称、主题和用户注记同样以安全文本呈现。

未来主题、未连接的主体和未找到实时生产者的通道都可以显示。无连接只能标为“未连接”；外部程序的运行状态应显示为“未知”，不能标为“已停止”。

连接的 `declaredId`、`role`、`displayName` 是声明或诊断信息。它们不能替代 Hub 的真实通讯主体，也不能因文字包含 `context`、`ui`、`harness` 或其他名称而获得特殊管理资格。

## 3. 三项接入管理操作

管理请求明确选择主体类型或本次连接标识，避免把同名的不同对象混为一项操作。

| 操作 | Hub 行为 | 持久性与显示含义 |
| --- | --- | --- |
| 暂停主体接入 | 保存该稳定主体的暂停状态，断开它当前的连接，拒绝它后续接入 | Hub 重启后仍暂停；不表示外部程序被停止 |
| 恢复主体接入 | 保存移除暂停限制的状态，允许 mod 按自身策略重新连接 | 仍须通过原有认证、主题 ACL 和容量检查；不保证立即连上 |
| 断开本次连接 | 关闭所选当前连接，不保存主体暂停限制 | mod 可以自动重连；过期连接标识不能误断一个后来出现的新连接 |

**单 ID 主体**指采用单桥身份接入的稳定主体。**credential 主体**指采用配置凭据接入的稳定主体；其当前连接可能表现为多个独立实例身份。暂停 credential 主体影响该凭据下的全部当前实例和后续实例，不只影响界面当前选中的某个声明名称。恢复不扩大该凭据的 ACL。

暂停与恢复属于 Hub 的通讯接入控制。它们不删除已接纳的记录、不重置消费游标、不伪造 ACK、不撤销已发生的业务操作。恢复后的历史抽取仍执行原有保留范围、过滤器、游标、确认和缺口规则。

暂停操作应在管理状态持久保存成功后报告成功并执行断连。状态写入失败须明确失败，不能宣称已持久暂停。重复暂停或恢复同一主体应具有一致结果；管理动作自身不能触发外部业务重做。

## 4. 程序与桥的关系仅作视图注记

用户可填写程序名称、注记及它与通讯主体的关联关系。该关联支持 **N:M**：一个程序可关联多座桥，一座桥也可被标注为服务多个程序。程序不必与桥一一对应，也不必各自占用一个独立进程。

这些注记仅帮助阅读拓扑。它们不参与 hello 认证、主题授权、路由、留存或执行决策，不证明程序已运行，也不证明该关联已经由程序自行确认。删除或修改注记不改变桥的通讯行为。

界面不启动、停止或重启外部程序，不向外部程序发送停止命令，不决定程序本地接口，也不要求 mod 使用某种宿主、CLI、浏览器、插件或 IPC 形态。

示例启动器使用 IPC 向它自己拥有的本地子进程表达停止意图，是参考程序的生命周期机制。它不是 wire 协议，也不是所有桥或所有程序必须采用的接入条件。

## 5. 管理状态与访问边界

`management.json` 保存稳定主体的暂停状态和用户视图注记，采用原子持久写入。默认跟随有效日志目录，`--log-dir` 同时隔离默认管理设置；`management.stateFile` 可指定独立位置。未创建过管理状态时使用空暂停集与可选 `management.annotations` 初始注记；已有用户文件优先。文件无法解析或结构无效时，Hub **拒绝启动**，不能静默恢复为空并意外开放已暂停的接入。即使消息日志关闭，管理设置仍单独持久保存。

管理 API 只返回所需元数据，不返回 ACL token、hello token 或包含这些值的配置原文。credential 标识可以用于选择稳定通讯主体，但不等于向界面公开凭据秘密。

`/manage` 及管理 API 仅接受回环访问，并校验合法的本机 Host。浏览器管理变更校验同源 Origin 与 CSRF token；本机 API 客户端即使没有 Origin，也须满足 Host 与管理请求的 token 校验。拒绝跨来源变更、非法 Host、非回环请求和无效 token。

这是本机管理入口，不是公网控制服务，也不提供本机不同用户或不同应用之间的账号隔离保证。数据面监听地址与管理面访问范围分别处理；数据面允许远端 mod 接入，不意味着远端能调用管理 API。

## 6. 留存与观测边界

信息的留存许可仍由提供者策略决定。管理界面不替提供者发送 `release`，不提供强制删除未释放信息的操作，也不因为提供者离线、被暂停、凭据移除或界面标注了程序关系而清理其记录。

当前参考日志容量是全局容量。最旧段仍受保护时，`LOG_CAPACITY` 可以拒绝所有提供者的新发布；这项限制不会因为新增管理界面而变成按提供者隔离。界面应诚实显示容量拒绝及保护状态，不把“有人读取过”或“连接已断开”视为删除许可。相关合同仍见[可靠性与访问边界](reliability-access.md)。

留存对话框显示最旧段未释放主体及序号、未使用段位、活动段距轮转目标、附件预约／剩余／可回收量和本进程 gap 落盘失败数。它们是只读通讯观测，不授予强制删除或业务管理权；未知历史身份显示未知，可回收预约不等于已经删除，目标剩余字节不等于精确可写容量。启动 ready、`/status.storage` 与管理摘要共享数据，详见[部署](../deployment.md)。

信息流来自真实 Hub 接纳、投递与管理动作的观测记录，采用有界近期样本。投递动作最多证明 Hub 执行了该次通讯动作，不证明接收程序已收到或业务已完成。ACK 表示该订阅提交了通讯消费确认；它不证明工具、渲染或其他程序业务成功。样本缺失、分页范围和记录保留范围应分别说明，不能把近期图当作完整历史。

## 7. 验证要求

下表是验证要求。实际执行与覆盖程度以本次测试结果为准，不能把本表当作已执行结果。

| 编号 | 候选验证内容 | 状态 |
| --- | --- | --- |
| MG-01 | 本机打开 `/manage`，管理界面通过通用管理 API 读取 Hub 元数据 | 按当前运行核对 |
| MG-02 | 使用任意新主题、新 opaque 载荷和任意桥声明名称，拓扑与通讯记录仍正确显示，无业务种类分支 | 按当前运行核对 |
| MG-03 | 发布、订阅和投递记录取自实际 Hub 动作；无接收者的发布也显示为已接纳通讯 | 按当前运行核对 |
| MG-04 | 信息流样本有界，并明确不能由投递、ACK 或样本图推导业务完成 | 按当前运行核对 |
| MG-05 | 暂停单 ID 主体后断现有连接、拒新接入，Hub 重启后仍保持暂停 | 按当前运行核对 |
| MG-06 | 暂停 credential 主体影响全部现有实例，并阻止新的声明名称或实例绕过暂停 | 按当前运行核对 |
| MG-07 | 恢复允许 mod 自行重连；原 ACL 仍拒绝未授权主题，不新增程序权限 | 按当前运行核对 |
| MG-08 | 断本次连接后可以自动重连；过期连接标识不误断新连接 | 按当前运行核对 |
| MG-09 | 管理状态保存失败明确失败，不误报持久成功；重复管理请求结果一致 | 按当前运行核对 |
| MG-10 | 管理状态重启恢复；缺失文件使用初始状态，损坏或无效文件拒绝启动 | 按当前运行核对 |
| MG-11 | N:M 程序／桥注记可编辑并持久恢复，修改注记不影响认证、路由与消息处理 | 按当前运行核对 |
| MG-12 | 无连接的外部程序显示运行状态未知；管理操作不启动、停止或重启外部程序 | 按当前运行核对 |
| MG-13 | 暂停、恢复、断连和注记不删除记录、不代发 release、不伪造 ACK 或游标 | 按当前运行核对 |
| MG-14 | 非回环访问、非法 Host、跨来源变更和无效 CSRF token 被拒绝 | 按当前运行核对 |
| MG-15 | 管理响应、页面和错误信息不输出 token 或含秘密的配置原文；用户文本安全显示 | 按当前运行核对 |
| MG-16 | 暂停或恢复后的历史抽取仍遵循原数据面合同，不额外执行示例业务操作 | 按当前运行核对 |
| MG-17 | 全局日志受保护而满时仍明确 `LOG_CAPACITY`；管理界面不能绕过提供者许可强删 | 按当前运行核对 |
| MG-18 | 通用管理面新增后 wire 0.1 发收、动态登记及既有通讯验收保持兼容 | 按当前运行核对 |
