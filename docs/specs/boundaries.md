# 世界枢纽的定位与边界

线协议为 0.1，通过特性协商扩展请求／回应、定向注入与大体积通讯。软件版本见 [package.json](../../package.json)。本规范按通讯职责组织，文件数量、示例程序类型和历史章节分类不是产品要求。

**枢纽是外部程序之间的信息十字路口。它规定与自己通讯的方法，不规定参与程序的形态。**

## 职责

枢纽接收符合接入与授权规则的 mod 桥连接，由桥声明通道和订阅，按通道名称匹配转交消息。它提供通讯身份、投递序号、确认窗口、受提供者保留策略约束的通讯存储及缺口通知。接线图、通道声明、订阅表、通讯日志和释放元数据是通讯状态。本机管理界面可观测这些状态、暂停或恢复主体接入、断开指定连接；程序／桥关联名称只作 N:M 视图注记，不参与路由或程序执行。

定向信封、可信请求回应关联、磁盘附件字节与分块进度也是通讯状态。调用和注入仅通过已接入的 mod 连接转交，目标程序自行决定查找信息和处理输入；枢纽不成为外部程序的执行器。一个程序可以同时建立多座桥，不需要合并其全部通讯接口。

程序可以是既有应用、插件、库、独立进程、sidecar、浏览器或其他系统。桥怎样嵌入、程序怎样启动、状态怎样保存、如何渲染和执行，由程序自行决定。参考实现采用独立进程，只是验证拓扑，不是接入限制。

桥是程序与枢纽协议之间的适配层。输入方向为程序→桥→枢纽，输出方向为枢纽→桥→程序。一个桥可以只发送、只接收或双向；`role` 只是注解，不能由角色获得额外权限。

## 提供者决定保留策略

发布时可以没有在线消费者、订阅或既有接收程序。枢纽成功接受的消息默认受保护，直到提供者经 mod 明确 `release`。其他程序后来可按主题与游标抽取；抽取非破坏，可有多个读者，各自维护消费进度。发送、抽取、ACK、`caught_up` 和断开连接均不释放记录。

提供者何时释放、是否长期保留、如何去重或实现单消费者策略，由其程序决定。枢纽只验证释放者的通讯归属并记录释放许可，不读取业务内容或建立业务保留 mode。`release` 允许之后随历史段轮转清理，不承诺立即删除、敏感撤回或独占领取。

存储容量有限，但容量不是覆盖受保护消息的许可。需要轮转而最旧段仍有未释放记录时，新发布先以 `LOG_CAPACITY` 拒绝，不回 `published`，既有记录保持。默认磁盘日志保存保护状态；显式关闭磁盘日志仅保证本次进程内存留存，跨重启和断电边界见 [可靠性与访问边界](reliability-access.md)。

## 开放通道与信息种类

通道名称由 mod 提供。桥可显式 `register`，也可通过 `publish`/`subscribe` 隐式声明通讯通道。枢纽没有内置业务通道列表，不预注册上下文、界面、harness、传感器或其他信息类别；允许订阅尚无生产者的未来通道。

信息种类及其字段由通讯双方约定，放在载荷中。枢纽不根据 `body.kind`、业务 Schema 或程序类别选择执行器、解释内容或决定目的地。管理员的主题授权规则只是访问上限，不是信息种类的穷举表。

新增一种信息不需要改枢纽源代码。需要双方理解的新应用协议，由这些程序协商；枢纽只检查线协议、通道语法、身份、权限及通讯限额。

## 禁止进入枢纽的职责

- 世界状态、实体模型、业务事务、业务 Tick 和业务调度。
- 智能体上下文组装、筛选、压缩、模型调用或决策。
- 业务界面结构、组件、人类工作流、审批业务。
- harness 的工具选择、本地命令执行、业务文件操作或业务权限判断。
- 载荷转换、业务幂等、过期命令是否执行、应用状态恢复。

这些能力可以由外部程序实现，并通过同一种桥互通。枢纽收到代码或命令文字时只转交，不执行。通讯 ACK 表示接收方提交了消费确认，不证明任何业务结果，也不代替提供者的释放许可；枢纽不得替程序判断何时业务完成。

## 可执行边界

| 不变量 | 验收含义 |
| --- | --- |
| 无业务状态 | 持久化仅为通讯日志/对象字节及其进度、保留/释放元数据、接入暂停与用户管理注记；外部业务状态不进入接线快照 |
| 载荷保持 | 转交和补课保留 body 原始 JSON 文本，不改键、数值或转义 |
| 不执行外部代码 | 不加载业务执行器、不运行载荷、不启动外部程序 |
| 无业务时钟 | 空闲不产生业务消息；通讯超时与心跳属于传输管理 |
| 无业务出站调用 | 枢纽通过已接入连接转交；外部系统调用由桥/程序负责 |
| 不臆造消息 | 每次发布产生一个消息记录；按订阅扇出是正常转交，流控缺口是独立通讯记录 |
| 通道由 mod 声明 | 任意新名称与任意业务 kind 经相同协议工作，不能依赖内置业务类别 |
| 留存由提供者释放 | 无消费者也可发布；未释放记录不可因容量轮转清理；消费确认不触发释放 |

字段白名单只能检查当前接口结构，不能证明以后所有新增字段都是业务字段。新增通讯字段须说明用途并验收；不能用固定字段数代替职责判断。

诊断叶字段的用途、值规则与命名行为验收入口登记在[diagnostic-contract.mjs](../../tests/conformance/diagnostic-contract.mjs)，覆盖 counters、storage.log（含capacity／主体聚合）、storage.blobs（含limits）及最近gap失败详情。I1使用登记派生的封闭结构和值关系检查；[diagnostic-contract.test.mjs](../../tests/conformance/diagnostic-contract.test.mjs)检查登记完整性、验收入口实际存在、未知字段与伪数值反例，并以真实通讯验证计数因果。新增字段须同步登记具体用途并提供对应行为验收；仅加入白名单、填写类别或注释计数不能完成验收。用途是否属于通讯、指定行为测试是否充分仍须人工审查，机器不能证明未来所有语义都正确。此登记只约束枢纽自己的诊断状态，不限制mod通道、载荷字段或程序形态。
