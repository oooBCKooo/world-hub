# 整合包运行实例的动态装配

本规格描述 Launcher 和可选 Runtime 的部署能力。Hub 不读取整合包、模块源码、能力业务或工作流，不决定程序形态，仍然只处理模块桥通信。

## 初始整合包与当前组合

`pack.json` 和 `pack.lock` 保存可发行、可审阅的初始组合。实例启动后，Runtime 可以在同一 Hub 上维护当前运行的成员和接线，不自动改写初始包。

当前组合用 `runId` 和单调递增的整数 `revision` 标识。新增成员、配置调整、启动、停止、移除、外部接入授权与撤销、故障策略调整，均需预览和明确接受。旧运行、旧修订、另一实例的审阅不能复用。即使一次启动失败，已经发生的运行变更也会使旧审阅失效；失败成员的确切所有权句柄保留供停止和清理。

运行中的组合变更只属于当前一次运行。运行记录保留装配证据，但重启不会自动把它当作新的发行组合。要在后续启动中继续使用这些变更，需要将当前受管源码载入工作台，再另存为新组合，或停止原实例后保存为其下一组合版本。

组合版本与模块版本分别管理。保存组合要求组合版本高于来源版本，不重写模块作者的版本。

## Launcher 操作

在已运行的整合包实例中打开「动态装配」。面板列出初始受管成员、本次运行新增的受管成员以及外部自运行成员，并分别显示进程状态、通信状态、就绪情况、源码声明、公开参数、能力接线和模块桥权限。

- **添加受管模块**：选择已导入的模块或发行源码目录，根据作者的部署声明填写参数、主题、桥槽和精确能力提供者。审阅源码、解释器、权限和接线后，将其登记为已停止成员。添加不会自动启动代码。
- **审阅启动／停止**：只控制 Runtime 实际持有的该成员进程树，不重启 Hub。启动再次核对源码和解释器；声明的启动前置成员必须满足要求。
- **调整参数与接线**：保留程序的公开配置和实际通信别名。需要先停止受影响的成员，再审阅修改，之后分别审阅启动。
- **审阅移除**：成员退出得到确认后，移出当前组合并撤销其接入身份。已有程序数据不作为删除源码的一部分清除。入口和依赖关系必须仍然有效。
- **授权外部程序／撤销接入**：只改变当前 Hub 上经过审阅的外部身份和通信权限，不安装或启动外部程序。
- **载入工作台**：从当前组合复制受管发行源码和公开接线。私有身份、令牌、程序状态、已准备依赖及外部程序源码不进入这个源码包。

这些操作不宣称任意程序可以热更新。程序收到的 `peers`、`bindings`、主题和公开参数是启动配置快照。新增消费者或改变提供者关系可能同时影响提供者和消费者；Runtime 会列出需要停止的成员，不把新业务授权悄悄注入仍运行的程序。修改完成后由使用者按程序约定重新启动。Hub 仍可在不中断其他连接的情况下处理经授权的新桥会话。

## 成员故障策略

`pack.json` 的可选字段 `lifecyclePolicy` 只接受下列显式选择。省略时，`packType` 为 Atomic（缺省类型）采用 fail-fast，Mesh 采用 independent；不能根据 policy 反推类型。两种启动预设均保留本文的动态操作，详见[双预设规格](dual-pack-paradigms-atomic-and-mesh-spec.md)。

| 值 | 初始组合就绪后的行为 |
| --- | --- |
| `fail-fast` | 成员非预期失败时停止当前组合。 |
| `independent` | 标记失败成员，保留其他成员及 Hub 的运行。 |

明确审阅的单成员停止不等于非预期故障。`independent` 不跳过源码、身份、连接和健康检查，也不证明依赖该成员的业务仍然可用。两型均按 autostart 选择初始计划成员；Atomic 本次选中集合须全成，Mesh 缺省允许非关键成员失败或等待前置，状态分别记录。两型能力绑定都不隐含启动依赖，after 由作者明确设置。critical 成员的实际关键故障仍停止全组。是否重试、等待、替代提供者或补偿业务，由程序和操作者决定。

面板可审阅修改当前运行的故障策略；该修改只有在导出或保存组合时才进入下一版 `pack.json`。

## 外部程序与身份边界

外部接入需明确提供成员 ID、桥槽、主题权限以及提供／需要的精确契约和接线。Launcher 不从程序名称推断这些内容，不给外部程序编造可执行入口或受管 PID。

授权结果含本次运行的连接配置。它只通过本次操作的私有领取结果提供：Launcher 第一次读取已完成的具体操作时返回 `connection`，随后清除该内存领取结果；操作列表、实例摘要和组合清单不含凭据。界面需点击「显示本次接入配置」才展开，关闭弹窗清除显示。配置包含私密令牌，应直接交给对应程序，不能写入发行源码或公开文档。领取结果丢失时重新审阅撤销和授权，不从公共清单恢复旧令牌。

外部程序的进程状态为未知／自管，通信连接与否可单独观察。停止整合包或撤销授权会撤销其通信能力，不向外部进程发送终止信号，不因观察到某个 PID 就接管它。

源码快照排除外部成员。若保留的受管成员仍从外部提供者获取契约、将外部成员作为启动前置项，或入口仍指向外部成员，导出会拒绝并要求调整接线。不能把缺少提供者源码或私有凭据的组合伪装成可独立运行的整合包。没有这些依赖的外部会话可继续留在原运行中，但不随源码包发行。

## HTTP 接口

以下接口属于具有本机授权和 CSRF 校验的 Launcher，不是 Hub 通信协议。Launcher 使用保存在实例私有目录中的 Runtime 控制身份访问确切监督者；控制 URL 只接受 `127.0.0.1`，同时核对磁盘和响应的运行身份。不要求监督者一定由当前 Launcher 进程启动，也不使用磁盘 PID 代替所有权。

| 接口 | 用途 |
| --- | --- |
| `GET /api/instances/:id/assembly` | 返回 `{assembly,runId}`，包括受管程序、外部接入声明、实际配置、修订与来源摘要；不返回控制令牌。 |
| `POST /api/instances/:id/assembly/preview` | 输入 `action`、当前整数 `expectedRevision` 和该操作参数，返回 `reviewId` 与审阅内容。 |
| `POST /api/instances/:id/assembly/apply` | 输入 `{reviewId,accepted:true}`，返回异步操作 ID；应用前再次核对运行、修订、源码和精确摘要。 |
| `POST /api/instances/:id/assembly/snapshot` | 可携带 `expectedRevision`，生成受管源码包，返回 `directory`、`origin`、`stateRequirements` 等工作台来源信息。 |
| `POST /api/instances/:id/assembly/save-preview` | 停止原实例后，派生候选源码并审阅新版本、确切运行来源和程序数据策略。 |
| `POST /api/instances/:id/assembly/save-apply` | 输入 `{previewId,accepted:true}`，应用已审阅的停止状态事务，返回异步操作 ID。 |

`preview` 支持 `add`、`configure`、`start`、`stop`、`remove`、`admit-external`、`revoke-external` 和 `set-policy`。受管操作使用 `componentId`；新增源码使用 `directory`；公开配置使用 `settings`、`topics`、`bridges`、`after` 与 `bindings:[{providerId,contract:{id,version}}]`。`set-policy` 使用 `policy`。外部授权显式提供 `provides` 和 `requires`；不传可执行程序路径。

运行层的 `runId`／整数 `revision` 与源码工作台的 SHA-256 `expectedRevision` 不是同一概念。保存接口中的 `origin` 携带运行身份、运行修订、初始包摘要与目标实例 ID，`expectedRevision` 则核对源草稿。不能替换其中一个来绕过另一个。

异步操作通过 `GET /api/operations/:operationId` 获取最终结果。外部接入的私密连接配置只在该操作完成后首次领取时出现；普通 `GET /api/operations` 不包含它。

## 保存回原实例

工作台的「更新当前组合」先确认停止原实例的全部受管进程，再审阅候选版本。修改范围可以包含当前动态增删的成员、源码、公开参数、桥权限、契约接线与故障策略；初始包 ID 和实例 ID 保持一致，组合版本必须递增。

工作台保存自动生成覆盖候选成员及仍存在数据目录的原样保留计划，并在最终审阅中展示：

| 情况 | 自动生成并须审阅的计划 |
| --- | --- |
| 候选成员已有数据 | `{componentId,mode:"preserve-opaque",businessCompatibility:"not-inferred"}` |
| 候选成员尚无数据 | `{componentId,mode:"fresh"}` |
| 移出的成员仍有数据 | `{componentId,mode:"archive-removed",businessCompatibility:"not-inferred"}` |

这些计划只决定字节保留的位置，不声明任意业务数据兼容。工具不猜测格式、不自动迁移，也不通过清空旧数据让不兼容程序启动。数据在审阅后改变、运行已经替换、初始包已改变或候选源码改变，均拒绝复用旧审阅。需要提供者迁移时另用明确迁移流程，普通升级的作者数据策略不会因此放宽。

保存使用实例所有权锁、候选源码复制、软件与私有持久数据快照、事务日志及可检测的恢复边界。运行时新增的真实成员持久数据也进入经过来源核对的快照范围；程序数据目录顶层的 `tmp` 及生成的运行、控制记录不进入恢复范围。提交成功后更新实际实例身份和锁，移出数据留在本次私有事务快照中。失败时尝试退回原布局；不能确认恢复时保留目录和事务状态，阻止下一次正常启动，供人工检查恢复。工作台内可直接审阅应用，存储页可另行审阅恢复实际保留的快照，见[整合包改装规格](pack-customization-spec.md)。

保存不回滚已经发送的信息、外部服务副作用或其他程序的业务状态。保存成功也不自动启动；新版本仍须重新审阅本次执行。

## 当前部署范围与验收

动态管理受可选 Runtime 的成员、源码、平台和解释器限制约束，不扩展为 Hub 的程序形态限制。一个当前组合最多 32 位成员。新受管源码仍需完整模块声明、可用解释器、精确契约和有限源码清单；同一模块 ID 不能选择不同版本或不同内容冒充同一源码。

当前动态变更仅支持 `trusted-local`。已经在容器或系统用户隔离 profile 下运行的实例会拒绝这些变更，不自动降级到本机执行，也不沿用不足以覆盖新成员的旧隔离授权。

主要验收覆盖实际模块的添加／启动／停止、Hub 进程不重启、真实外部桥接入和撤销、独立成员故障、变更后的源码重新核对、陈旧审阅拒绝、源码快照排除凭据和外部源码，以及停止后保存原实例新版本并重新审阅启动。具体自动化证据见 `tests/integration/launcher/runtime-assembly-http.test.mjs`、Runtime 动态装配测试和保存事务测试。
