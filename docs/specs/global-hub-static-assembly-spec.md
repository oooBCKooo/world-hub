# 本机 Hub 静态装配与组合版本更新

本规格定义 Launcher 部署层的装配功能。Hub 仍只负责模块桥通信；不读取装配清单、不定义业务种类、不决定程序形态或数据格式。

## 1. 目标和边界

本机 Hub (`launcher.default`) 的受管模块能像整合包一样进入装配工作台：查看模块、修改公开参数、选择契约提供者、审阅主题和桥权限。工作台有两个出口：

1. **另存为新组合**：将草稿导出到新目录，生成当前格式的 `pack.json` 和 `pack.lock`；随后可导入独立实例。
2. **更新当前组合**：提升组合版本，审阅后更新原目标。无需为了每次参数或接线调整都创建独立实例。

组合版本与模块版本独立。提升组合版本不改模块作者的源码、模块 ID 或版本。界面默认建议下一补丁版本，可填写合适的新版本。更新当前组合必须保持组合 ID 并严格递增版本。

| 目标 | 更新当前组合的行为 |
| --- | --- |
| 本机 Hub 受管程序 | 停止全部受管程序后，审阅并一次保存现有模块的公开参数、主题、桥权限、契约接线以及组合版本。保留身份、源码、解释器选择和私有数据；不自动启动。 |
| 独立来源整合包 | 保持目录与包 ID，验证新源码与锁后更换来源包；原完整来源树保留在返回的恢复目录中。 |
| 已安装整合包实例 | 停止实例后，在工作台直接审阅并保存改装；沿用实例身份和目录，自动保存私有快照，保留仍在组合中的数据，归档移出成员的数据。保存后重新审阅启动。 |

本机 Hub 的原组合更新当前只支持**现有、相同源码模块的配置、接线与启动计划**。增删模块、替换源码及整合包生命周期配置使用另存；不假装这些更改已应用到本机 Hub。整合包实例的直接保存允许受审阅的拓扑变更，原样保留数据而不推测业务状态可迁移。

运行中的整合包另提供[动态装配](dynamic-pack-assembly-spec.md)。从该入口载入的实际运行组合可以在全部所属进程退出后，按明确的数据保留策略保存为原实例的下一版本，包含受管成员增删。它与本文的本机 Hub 静态配置更新各有明确目标，不改写正在运行的锁定基线。

## 2. 受管模块与外部接入

“静态装配”指装配 Launcher 已登记的源码，不是给模块或业务定义固定类别。

| 维度 | Launcher 托管的本地模块 | 外部接入程序 |
| --- | --- | --- |
| 来源 | 登记时复制并审阅的源码、模块声明和配置 | Launcher 未登记其部署源码 |
| 生命周期 | Launcher 持有本次创建的进程句柄并管理启停 | 程序或其他工具自行管理；进程状态未知 |
| 运行连接 | 根据真实认证主体、桥槽和存活进程句柄映射 | 未匹配到受管进程的真实 Hub 会话 |
| 源码装配 | 纳入所有已登记程序，包括已停止的程序 | 不纳入源码包，不凭会话名称推断源码或创建占位模块 |

外部接入不等于没有源码。本规格不增加尚未支持的 Stub 格式，也不接管未知 PID。一个程序可以有多座桥，多个程序实例可以引用相同模块源码。

## 3. 界面流程

1. 在本机 Hub 详情点击带工作台图标的 **静态装配 / Static Assembly**，或在 **静态模块与权限 / Static Modules & Permissions** 中打开装配入口。
2. 后端从受管注册表生成不执行程序的源码快照；工作台读取有效包、锁和来源 revision，打开并自动保存装配草稿。
3. 保留每个程序实例的 ID、公开参数、完整主题别名、各桥槽权限以及精确版本的能力绑定。禁止按模块库 ID 回找任意版本替代受管副本。
4. 在画布选择模块、移除或增加契约接线；编辑公开设置。配置编辑器同时提供程序主题别名和包级主题键，显式检查其对应关系。
5. 在导出页选择启动入口和组合新版本，然后另存，或更新原组合。进入工作台和编辑草稿均不改变正在运行的配置。
6. 本机 Hub 更新先要求所有受管程序确认停止；先生成审阅，再明确应用。应用后重新载入当前版本，逐个审阅启动，或审阅执行保存的启动计划。外部程序不受此启停操作管理。

工作台也保留本机 Hub 启动计划的 autostart 与 after。原组合更新可以一起保存成员选择和明确顺序，不能将能力绑定暗中转换为启动依赖。计划保存和执行分别处理，具体规则见[启动计划](startup-plans-spec.md)。

公开模块卡片显示后端实际声明、解释器类型、入口、受管源码目录和登记文件数量；缺失值显示未知，不猜测 Node.js 或文件数。契约提供关系不是程序实际启动顺序。

运行时桥面板来自 Hub 真实会话，显示真实 session、认证主体及归属。断线的受管程序仍是受管程序，不能改标外部。连接、进程、就绪报告和业务成功分别表达。

## 4. 数据与一致性

### 4.1 快照

`POST /api/programs/assembly` 接受可选 `entry`，返回 `directory`、`pack`、`composition`、来源范围和不执行标志。`composition` 包含稳定 ID、版本、名称及当前登记配置和源码的 revision。

快照与登记、删除、更新共用注册表串行队列。核对受管源码文件清单和摘要，复制时再次验证。只复制源码；不复制身份令牌、状态、日志、运行配置或已安装依赖。同模块不同实例保留各自配置；相同模块 ID 对应不同源码或版本时明确拒绝合包。

当前包模型最多 32 个组件、64 个不同具体主题；超限拒绝，不静默漏选。装配、作者配置及草稿请求的 HTTP 上限为 3 MiB，草稿存储仍有独立总量限制。旧锁格式不迁移或回退。

### 4.2 主题别名

包级主题键可自动生成短键；具体主题值保持原样。组件的可选 `topicAliases` 显式表示程序别名到包级主题键，例如：

```json
{"topicAliases":{"request":"t0","reply":"t1"},"bridges":{"main":{"publish":["t0"],"subscribe":["t1"]}}}
```

程序运行配置收到自己的别名及具体主题。两个程序可以使用相同别名但指向不同主题；未授予桥的别名也保留。映射本身不授予访问，实际权限仍由桥 ACL 决定。未知主题、重复目标或 ACL 引用映射之外的主题均拒绝，不能靠数组位置猜测或自动扩大权限。

### 4.3 原组合更新

`POST /api/programs/assembly/preview` 接受来源目录、草稿包和登记配置的 `expectedRevision`，返回有限时效的审阅。`POST /api/programs/assembly/apply` 接受 `reviewId` 和 `accepted:true`，重新检查源码、当前配置、停止状态、版本及契约后提交。

组合元数据和所有新公开配置在同一次注册表写入中保存；持久化失败恢复内存配置。任何登记变动、源内容变化、过期审阅、运行中程序或同版／降版都会阻止更新。草稿恢复可以带来源 revision，但不能恢复执行或应用授权。

独立来源更新使用 `POST /api/authoring/update`，保持目录并保留可恢复来源树。实例来源不可通过该接口直接改写；工作台通过实例专属的改装预览与应用完成保存，复用停止锁、私有快照、事务恢复与执行重审。候选生成只是内部准备步骤，不能提前显示已更新。恢复目录也保留额外作者文件；新来源只包含经过核对的包、模块和来源记录。来源标识与回退边界见[整合包改装规格](pack-customization-spec.md)。

### 4.4 多界面

可信本机执行可有多个声明 loopback 监听权限的程序报告有效界面 URL；逐项验证协议、主机、端口和凭据。`entry.component` 只选择整合包主界面，不限制其他程序拥有自己的界面。容器隔离的 HTTP 通道策略保持独立核对。纯后台组合不要求界面 URL。

## 5. 实现与验收

- 部署层：`global-hub-assembly.mjs`、`global-hub-update.mjs`、`local-programs.mjs`、`composition.mjs`。
- 工作台：`public/advanced.mjs`；本机 Hub 详情：`public/app.mjs`；持久草稿：`creator-drafts.mjs`。
- 包与运行契约：`package.mjs`、`deployment.mjs`、`authoring.mjs`、`authoring-update.mjs`、`runtime.mjs` 及公开 pack Schema。

验收包含真实的跨语言快照、换提供者、派生包导入与运行；原组合停止后更新、保留数据和身份、重启 Launcher 后再次通信；相同模块多个实例、多界面、自定义别名与拒绝越权主题；外部会话排除；运行／内容变化／过期／版本错误及写入失败拒绝；中英文界面和发行文件完整性。
